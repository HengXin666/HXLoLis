# 推荐方案与授权

取证阶段在 docs/reference/quality/inventory.md 给出架构与依赖两类推荐, 包括保留现状的结论. 说明问题证据, 可复用实现, 候选比较, 推荐理由, 迁移与回退, 影响路径和验收命令. 安装阶段按已选方案实施, 验收阶段补上实际结果

## 推荐产物

- 架构方案包含现有模块与依赖方向, 公共接口, 内部实现, 数据端口, fake/real 边界, 前后端契约映射. 比较保留现状/局部调整/整体迁移, 不适用项说明证据. 给出具体路径和分步迁移, 不用包许可证字段代替架构比较
- 依赖方案按项目实现, 标准库, 已用库, 新库依次取证. 满足需求即可停在该层, 不为了凑候选引入新包. 确需新库时比较至少两个可行候选, 只有一个时记录检索范围与淘汰依据
- 包比较记录版本范围, 许可证, 维护状态, 发布时间, 实测体积或未测说明, 安全公告, 兼容性及来源 URL/查证日期. 不凭记忆编造最新版本或性能数据

## 授权边界

推荐与实施授权分别记录. 复用已有能力和任务范围内的常规可逆调整直接实施. 新增直接依赖, 跨大版本升级, 技术栈迁移或超出任务范围的架构变更, 先核对本次任务与会话中已有授权; 已授权即实施并记录依据, 仅未授权的选择需要用户决定

需记录授权的选择写入版本化 scripts/quality/approvals.json, 格式参考 assets/approvals.example.json. 补丁/小版本与仅 lockfile 传递依赖变化不要求审批单, 仍由 HC-DEPS review, 标记 review-only. 待决定方案可保持 proposed, 不阻止已授权且无依赖关系的安装工作

| 字段 | 内容 |
|---|---|
| id | APR-<kind>-<slug>, 全仓唯一 |
| kind / subject | dependency, architecture 或 stack; 包名与版本范围或精确模块路径 |
| need / reuse | 问题与文件证据; project, stdlib, existing 各写已查位置或不适用原因 |
| candidates | 依赖使用包比较字段; 架构使用边界/耦合/迁移成本/运行约束, 保留复用现有选项 |
| choice / impact | 推荐与理由, 回退, 改动路径, 迁移步骤, 测试 ID 与验收命令 |
| status | proposed, approved 或 rejected |
| authorization | 已有用户指令或本次决定的准确摘录与来源, 不把 Warning 或沉默当作批准 |
| approvedBy | 有真实授权时填授权者, 不猜用户名; proposed/rejected 不填批准人 |

先把方案和可验证的局部实现准备好, 确需确认时一次列出待决定选择. 已有授权直接登记 approved, 不重复确认. rejected 保留拒绝理由, 需求或证据变化才能提出替代方案

## 门禁关系

HC-REUSE 检查推荐产物和逐级复用证据, HC-DEPS 列出每项依赖变化及 approved/unapproved/review-only 状态. approved 必须匹配 subject 范围与真实授权依据; 降级或超出批准版本范围重新裁决. 两项为 Warning, 不把全部依赖变更升级成人工审批. 未授权的必要选择记录 blocked, 不执行依赖它的变更, 不把它计作安装完成
