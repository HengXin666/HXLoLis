# 红绿循环契约

每轮只做一个纵向切片: 一个接缝, 一条测试, 一份最小实现. 上一轮学到的东西决定下一条测试. 禁止先写完全部测试再写实现 (水平切片), 那样测的是想象中的形状, 对真实行为变化不敏感

红: 先写测试, 用项目 runner 只运行这一条测试 ID, 确认它因断言不满足而失败; 修 bug 时被测代码抛出与该 bug 相符的异常也算红. 红绿记录注明失败类型. 因导入错误, 语法错误或环境缺失而失败不算红, 先修好测试本身

绿: 只写让这条测试通过的最少代码, 不预支后续测试, 不加推测性功能, 再只运行这一条确认通过

修 bug 时先写复现该 bug 的测试并看到它红, 再修复. 实现已存在的探针或回归测试, 先临时破坏输入或被测代码确认测试能红, 再恢复后确认变绿, 不接受从未红过的测试

期望值来自独立事实源: 已知字面量, 手算示例, 规格或契约 YAML. 不按实现同样的算法重算期望, 见 `references/tests.md` 的同义反复一节

循环中不运行完整测试集, affected 选择, formatter, lint 与 notes 门禁. 重构不在循环内, 所有切片变绿后才整理代码, 整理不改断言, 由交付步骤的末轮运行验证

同一条测试连续两轮仍无法按预期变红或变绿时停止该切片, 记录现象并标 blocked, 不改断言迁就实现

产物是每轮的测试与实现 diff, 以及每条测试的红绿记录 (命令和结果摘要)

通过条件是接缝表中每一行 (主路径, 失败路径及另列的分支) 各有至少一条先红后绿的测试, 或逐行标 blocked 并写明原因
