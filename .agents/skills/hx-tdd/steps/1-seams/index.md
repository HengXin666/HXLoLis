# 接缝确认契约

只确定要测哪些公共接口, 不写测试, 不改实现

先读根 AGENTS.md 与 `.agents/coding-rules.md` (存在时), 目标声明顶部引用的 Agent Note, 项目已有测试目录, runner 与统一入口, 以及 hx-agent-code 的 coverage.json 与模块表 (存在时). 测试名与接口用语沿用 notes 和代码中的领域词, 不自造同义词

接缝是观察行为而不深入内部的公共边界, 如模块导出函数, HTTP 端点, CLI 命令, 前端请求层, 页面交互. 私有函数, 内部协作者与配置常量不是接缝

骨架上限: 每个接缝先只列主路径和一条最有价值的失败路径. 复杂分支或关键业务逻辑另列一行并写明理由, 其余边界情况不列. 承接 hx-agent-code 登记清单时清单项原样保留, 不套用此上限. 测试不追求覆盖率数字, 追求关键路径有可执行规格

接缝表每行包含接缝, 测试层, 用例 ID 草案, 能抓到什么, 抓不到什么. 接口形状本身存疑 (模块该多深, 边界放在哪, 该暴露什么) 时在表中给出推荐与影响, 不靠测试绕过

产物是接缝表, 一次交给用户确认; 承接 hx-agent-code 登记清单时直接以清单为接缝表

通过条件是每个接缝已确认或来自登记清单, 层与目录已确定, 单条测试 ID 的运行命令已用项目已有测试实测可用; 项目尚无测试时, 该命令在循环首条红灯中验证
