# 红线类型目录

七类判据的形状、代价、以及**什么时候不值得做**. 选型时按这张表问自己: "这个仓库的失败史里, 有哪一类对应得上?"

**这张表是选型用的, 不是采购清单.** 七类全装在任何仓库上都是错的  没有对应证据的类别不要装, 这是"禁止照搬"的具体执行方式

---

## 1. lint / 格式 / 静态类型

- **拦什么**: 语法风格、明显错误、类型不一致
- **判据**: 用现成工具(ruff / biome / eslint / tsc / vue-tsc / mypy), 不自己写
- **代价**: 低, 秒级; 自动修复是标配
- **什么时候不值得**: 编码规范还没稳定时先别锁死格式, 否则每个 PR 都在改格式
- **要点**
  - 格式化命令应该**自动修**而不是拒绝(pre-commit 用 `--write`)
  - 被关掉的规则要**留痕**: 配置里 `ignore` 掉的规则, 用棘轮冻结现有违反数(见类 3)
  - 类型检查放 CI 与 push, 不放提交路径(大项目会慢)
  - **配置已存在但从不执行**是很常见的形态(`"strict": true` 而全仓没有 `tsc` 脚本)这类是合格的预防性红线, 但首跑会冒出一批存量错误, 先只跑不阻断, 看到清单再决定棘轮还是清零

## 2. 架构与分层

- **拦什么**: 文件行数、目录文件数、命名约定、依赖方向、外部调用的收口
- **判据**: 需要读代码结构 Python 用 `ast`, TS 用编译器 API. **正则在这里会误报** (字符串里的 `fetch(`、注释里的示例代码). 躲不开正则时必须限定词法边界并接受少量误报
- **代价**: 中, 取决于扫描范围; 通常秒级
- **什么时候值得**: 用户/宿主已经规定时按标准落实; 否则以结构失控、重复违反或明确预防风险为依据(见 ../../1-evidence/impl/evidence.md). 没有历史事故不构成跳过明确标准的理由
- **要点**
  - 阈值必须按这个仓库的现状定, 算法见下面「阈值怎么算」
  - 依赖方向这类规则, 判据要写清"哪个目录不准 import 哪个", 而不是抽象地说"注意分层"
  - 行数豁免必须带**登记上限**(如 `路径|N`): 挂了豁免的文件长过 N 依然红
  - 超限时的修复动作要写进报错信息(如"拆到 `impl/` 子目录"), 而不是只说"太长了"

## 3. 棘轮(存量欠账)

- **拦什么**: 已有的违规**只许降不许涨**  新增即红
- **判据**: 一份基线文件(规则 → 现有违反数 / 现有豁免条目集), 每次运行对账
- **代价**: 低
- **什么时候值得**: 几乎总是值得, 只要仓库已有存量欠账
- **要点**
  - 棘轮是"今天就能装上门禁"的关键. 没有它, 只能选择"全仓清零"(一个巨大的修 lint PR)或"不装"
  - 基线**同时记方向和数字**: 光有数字, 悄悄删一条豁免再补一条新违规(总数不变)就绕过去了
  - 基线文件要进指纹(见 `self-defense.md`), 否则它可以被改大

## 4. 契约快照

- **拦什么**: 对外表面与代码不漂移  路由、请求/响应结构、生成的类型、配置目录
- **判据**: **生成 + diff**. 从代码生成一份快照文件, 提交它; 门禁重新生成并与提交的比对
- **代价**: 中(要跑生成器), 通常不连库不起服务
- **安全约束**: 生成器若需要 `import` 应用或框架入口, **先确认 import 没有启动副作用** (建连接、绑端口、起事件循环、写日志文件). 有副作用就退回静态抽取(ast / 编译器 API) 一条只读的分析不该把一个服务跑起来
- **什么时候值得**: 有外部消费者(前端、其它服务、SDK), 且契约变更的代价高于维护快照的成本
- **要点**
  - 快照的**集合对账**比格式对账更值钱: 新增了一个接口却没登记, 和删了一个接口却没删快照, 都要红
  - 生成器要能 `--check` 模式: 只比对不写盘, 让 CI 用
  - 契约快照和"顺序测试"(如路由注册顺序)是互补的两把尺子

## 5. 接线

- **拦什么**: 东西做出来了但**没接上**  路由没挂载、模块没导入、配置项没被读取、门禁没被注册
- **判据**: 扫描式  找出定义点与使用点, 断言两边存在
- **代价**: 低
- **什么时候值得**: 只要有"注册/挂载/导入"这类隐式契约就值得
- **要点参考**: 门禁自身有没有被接进检查点, 属于本类问题; 判据与负向探针见 templates/skeletons/03-probes.md (相对 skill 根)
- **要点**
  - 这类 bug 的特征是**单测全绿但功能不可见**, 靠测试很难捕获
  - 它同时适用于产品代码和基础设施: 门禁有没有被接进检查点, 属于同一类问题
  - 接线类的门禁最容易**因为一次改名而静默失效**  它必须有负向探针

## 6. 文档上下文(注入层)

- **拦什么**: 每轮都要付一次的常驻文档  体量超预算, 以及规则堆错层(只该一个子目录读的东西留在根)
- **判据**: 逐目录扫描入口文档的字节数, 加上"权重达标的目录必须自带入口文档"; 事件驱动不适用, 这是结构判据
- **代价**: 低, 秒级; 目录遍历两次即可
- **什么时候值得**: 只要仓库在用入口文档注入 AI 上下文就值得. 本仓的形态是根有一份、子目录一份都没有, 于是模型只读到全局规则
- **要点**
  - 体量是**上限**, 分层是**覆盖**: 只做前者, 结果是根文档删到阈值内仍然全是全局无关内容
  - 存量几乎必然超标, 必须配**棘轮基线**; 基线条目不再缺失时要判红, 否则它会掩盖已经做完的修复
  - 阈值按本仓实测定, 不要抄别的仓库; 纯文档目录也要算, 否则 `docs/` 这种最大的目录会整个漏掉
  - 降级顺序固定: 先搬层, 再压缩, 最后才抬上限

## 7. 元门禁(门禁自己的门禁)

- **拦什么**: 门禁本身失效、被悄悄放松、或没有被接上
- **判据**: 三类, 见 self-defense.md 棘轮管方向、指纹管可见性、探针管有效性
- **代价**: 探针最贵(要起几十个子进程, 每条规则两组用例), 所以它**不进 Stop hook**, 由 CI 与手动命令承担
- **什么时候值得**: 从装第二条门禁开始就值得
- **要点**: 一个永远 PASS 的门禁和一个正确的门禁, 在 CI 上是同一个绿色. 没有元门禁, 红线集会在半年内退化成装饰. 元门禁自身也要有覆盖检查(如分流表覆盖、指纹来源对账)

## 阈值怎么算

先区分用户硬标准与待选参数: 前者按规定执行, 存量另设过渡; 后者才按下面方法测量现状、建议阈值并确认. 参考快照与 p90 都不能自动覆盖用户指定的 300 行等上限

```bash
# 以"单文件行数上限"为例。先看分布, 不要先定数字
git ls-files '*.vue' | xargs wc -l 2>/dev/null | sort -rn | head -20   # 头部: 谁超标
# 再用任意方式算 n / min / median / p75 / p90 / max(awk、node、python 各一行都行)
```

判读方式

- **上限取 p90 附近**(或 p75, 如果 p90 已经被少数巨型文件拉高). 它的含义是"允许绝大多数文件自由生长, 只卡住最离谱的那几个"
- **已经超标的文件全部登记为棘轮基线**, 各自以**当前值**为上限, 只拦继续增长. 于是第一批就能全绿
- **p90 与 median 贴得很近时**(分布平坦), 说明这个维度不是问题, 别装
- **median 已经贴着别人的阈值**(比如别人写 ≤500 而本仓 median 499) 这正是照搬会翻车的信号, 必须按本仓重新算

同理适用于目录文件数、函数长度、依赖边数量. **没算过的数字不要写进判据**

## 先装哪一类

不是清单, 是排序依据  先装"成本最低 + 误报最少 + 能立刻跑通回路"的那一类, 用哪个类别取决于这个仓库的现状

- 有明确违反证据的类别(第二节对数出来的)→ 优先, 因为它的价值已经证明过
- 配置已存在但零执行的(如 `strict` 没跑)→ 次优先, 成本近零
- 纯"惯例该有"的(如格式化)→ 最少优先, 标预防性
- 需要新建基础设施才能跑的(如契约快照的生成器)→ 最后

一次只加一类. 每加一类, 先问"它拦的是哪次真实失败"
