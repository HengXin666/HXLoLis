# 门禁总线契约

**一个注册表 + 一个入口脚本, 被所有检查点共用. ** 不要为每个检查点各写一套调度  那正是"本地一套、CI 一套"的来源

注册表的一行描述一条门禁; 入口脚本负责把选中的门禁按顺序跑起来并如实报告

## 注册表字段

|字段|作用|
|-|-|
|`group`|所属分组, 由命令行开关选择(如 `backend` / `frontend` / `notes` / `guard`)|
|`label`|显示名. **它写着这条门禁拦什么**  别写成命令的复述|
|`cmd` / `args` / `cwd` / `env`|怎么跑|
|`fastArgs`|加快档下替换 `args` 的那一份(只给"慢的部分是可选"的门禁用)|
|`produces`|这条门禁在**本次运行**里产出的逻辑产物名|
|`requires`|依赖某个产物由本次运行产出; 没产出就**跳过并说明原因**|

分组开关的意义是让不同检查点各付各的账: Stop 跑一条 lane, push 跑几条, CI 跑全部分组

## 硬约束: 扫描根必须可被覆盖

**每个门禁脚本都必须允许用环境变量把它的扫描根 / 白名单 / 基线路径指向别处** (仓库根、清单路径各一个变量即可)

这不是洁癖, 是探针能不能存在的前提: 负向探针要把扫描根指向一个临时目录、往里放故意违规的夹具、断言门禁 FAIL, 然后跑完即删、绝不碰真实仓库. 一个把路径写死的门禁**没有输入可喂**, 于是"证明它会红"这一步根本做不出来  而那一步正是红线成立的第三个条件

同理, 门禁脚本要能接受"只读"的运行方式(`--check` / `--list` 这类), 供 dry-run 与人工排查使用

## 五条防"跑错"的机制

这些机制全部来自同一个观察: **门禁最危险的失败形态是"它看起来跑了"**

1. **未知参数直接退出并报错**(exit 2). 把新 flag 静默当成分组名, 会让"我明明传了开关" 变成"跑的是别的东西". 合法参数必须是闭集, 其余一律拒绝
2. **preflight**: 门禁脚本文件不存在时立刻报错, **不是当成通过**. 少这一步, 一次改名会让整条门禁静默消失
3. **`produces` / `requires` 只认本次运行**: 依赖覆盖率之类数据的门禁, 必须只认这一轮跑出来的产物. 漏掉这条判断, 它会读到上一轮留在磁盘上的旧文件而**静默变绿**  那比跑得慢危险得多. 配套约束: 走了加快档就**不记** `produces`(快档产出的是子集)
4. **fail-fast**: 第一条红就停, 并打印**复现命令**(`cd <cwd> && <cmd> <args>`). 让人和 agent 能一条命令重跑失败的那一步
5. **`--dry-run`**: 只打印会跑哪些门禁与它们的真实参数, 不执行. 写文档、排查"到底跑了什么"、做 code review 时都需要它

## 输出约定

- 每条前打印进度与序号, 后打印耗时  让人知道慢在哪一条
- 全部通过时打印一行明确的成功标记(如 `ALL PASS`), 便于脚本与 CI 判断
- 失败时打印 `FAIL <序号> <label> (exit N, X.Xs)` + 复现命令, 然后立即退出, 退出码沿用失败门禁的

## 语言分工

- **分析某种语言的代码, 用它自己的解析器**: Python 用 `ast`(写 Python 脚本), TS 用编译器 API. 用正则去分析语法结构是误报的温床
- **其余胶水一律用一种语言**(通常是 Node, 或仓库已有的脚本语言), **不要再新增第二种**. 每多一种语言, 就多一个 CI 镜像、多一套依赖、多一份"这段逻辑在哪实现的"的困惑
- **不新增 shell 脚本**做调度  退出码、引号、错误传播在 shell 里全是坑, 而它不带来任何好处

## 新增一条门禁的做法

往注册表里追加一行, 不要另起一套调度脚本. 追加时同时问自己

- 它属于哪个分组? (不在任何分组里 = 永远不会被跑到)
- 它的扫描根能不能被环境变量指向别处? (不能就写不了探针, 见上面的硬约束)
- 它有没有负向探针? 没有的话, 它是不是"装饰性"的?
- 它会不会拖慢 Stop 阶段? 会的话要不要只放在 CI

## 与检查点的关系

注册表定义的是"有哪些门禁、怎么跑"; 检查点定义的是"什么时候跑哪些分组". 两者分开, 才能既保证定义唯一, 又让不同层各付各的账

**接线本身要能被校验**: 从注册表删掉一行, 这条门禁会在所有检查点上同时消失,
而"它有多严"没有任何变化  所以严格度快照拦不住它. 机制见 `self-defense.md` 的「指纹」与「探针」两节
