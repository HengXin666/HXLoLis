# Python 项目候选标准(逐条裁决, 不得静默跳过)

这份是明确的默认评审模板, 而不是宣称任何仓库已经执行. 进入目标项目后, 先查根指令、现行格式器、Python 版本、生成文件、测试与已有例外; 逐项在项目全景文档中写 **范围 / 判据 / 现状证据 / 采用或偏离 / 落地点 / 正反探针**. 用户或宿主更严格的规定优先; 调整或不采用一项须给可复核理由, 并在落地前让用户确认, 不能以"本仓中位数较高"自动放松用户指定上限

## PY-01 单个 Python 源码文件不超过 300 行

默认仅计项目维护的. py 源文件(包含注释和空行的物理行), 排除自动生成、第三方与缓存文件; 测试、迁移脚本是否纳入要在全景里逐目录决定, 不得悄悄排除. 现有 >300 行的文件单列路径和当前行数; 目标规则仍为 300, 存量可按逐文件"当前行数只降不升"的临时棘轮过渡, 新增文件直接按 300 拦. 不得因为新行数低于一个超标文件的旧基线, 就把新文件放行. 若用户明确要求立即清零, 则列出拆分工作量后按该要求执行

判据可用跟踪文件列表 + 行数计算; 正反探针覆盖第 300/301 行、新增超标、现有超标增长、文件删改后的陈旧豁免. 报告和修复路径写入失败信息, 不把阈值固定写在无法检查的文档里

## PY-02 注释与函数参数保持一致

对公开函数、对外接口及宿主指定的重要内部函数, 采用该项目既有 docstring 风格(包括原版的 @param/@returns, 也可为 Google、NumPy、reST 等); 没有既有风格时提出一种并由用户确认, 不凭空混用或自动改写宿主风格. 格式器统一空白、缩进与换行; 参数文档须与签名中的参数名逐一对应, 新增、删除、重命名参数时同步调整说明、返回值/异常和示例中相关约束. 类型、默认值及实际行为与文档不一致时以真实实现/契约为依据修正, 不为了过检查凭空填空话

分清机械与语义: 可用 AST 取签名、相应 docstring 解析器核对参数名和文档段, 格式由项目格式器执行; "说明是否准确"须对照实现、调用方和测试作人工复核. 是否要求所有私有函数有 docstring 按目标项目既有规则和复杂度裁决, 避免生成无意义注释

## PY-03 函数变更必须核对受影响契约

变更签名、返回结构、异常、可观察行为或公开调用方式时, 检查调用点、测试和对应 docstring; 有对外 API / 配置 / 生成契约时同步更新这些资产及其验证. 纯实现重排而行为不变, 写明不需要更改的理由, 不能凭"函数改了"强制改无关文档. 用基线 diff 定位变更函数及其调用面; 脚本只核查可判定的签名/文档漂移, 语义影响由测试或评审确认. 负向探针包括重命名参数但保留旧 docstring; 控制组包括只重排函数内部的实现

## PY-04 导入位于模块头部, 禁止随意局部导入

对项目代码默认禁止函数体/类方法中的 import 或 from import; 先从 AST 检查导入位置, 不用正则误判注释或字符串. 唯一例外必须是确有循环依赖破局、可选重依赖延迟加载、平台条件导入等具体需求; 逐项登记路径、符号、理由和退出条件, 优先改模块依赖结构而不是永久豁免. TYPE_CHECKING 分支、测试夹具及工具生成代码是否另算, 按项目实际用法逐项决定. 负向探针在普通函数内加 import 应 FAIL, 模块头 import 与登记且真实必要的例外应 PASS

## 生效门槛

每条写清采用状态: **标准已记录 / 判据已实现 / 本地已接线 / CI 已接线 / 负向探针已跑**, 不能用一个勾代替五个状态. 项目没有 Python 时写"无 Python 源文件, PY-01..04 不适用"及扫描证据; 有 Python 时必须给四行裁决, 不能只写"按项目情况处理"
