# 检查点分层

同一套判据被多个检查点调用, 但**每层的预算和职责不同**. 核心原则一句话: **越慢的检查点越会被绕过, 最后等于没有. ** 所以快而能自动修的放前面, 贵而全的放后面

## 分层表

|层|触发|跑什么|预算|
|-|-|-|-|
|**PreToolUse**(agent)|每次工具调用前|拦不可逆命令、受保护路径的编辑|毫秒级, 超了会拖慢每一次调用|
|**PostToolUse**(agent)|每次写/改文件后|只处理本次改的文件: 格式化、去零宽字符. **不阻断**, 失败只提示|< 3s, 超了移到 Stop 或设 async|
|**Stop**(agent)|每轮结束|只跑**本轮改动落在的那条 lane**, 失败就让 agent 继续修|秒~分钟|
|**pre-commit**|`git commit`|只碰**暂存文件**: 格式化、空白检查, 以及快速确定的阻断检查(例如宿主 note 覆盖)|按项目实测|
|**pre-push**|`git push`|与本次改动相关的最小严格检查, 可并行|≤ 60s|
|**CI**|push / MR|完整矩阵、覆盖率、e2e、契约、元门禁与负向探针|分钟级, 但别让 PR 干等|

分工原则: pre-commit 优先做快而可修复的事; 快速确定性的阻断检查也可放入, 实际成本按项目测量. 贵的东西(覆盖率、e2e、全部负向探针)在 push 与 CI 各付一次, 不进提交路径

**表里的秒数是量级参考, 不是可以照抄的判据.** 它们来自"人的等待耐心"与"agent 每次工具调用的成本", 不是来自任何仓库的失败史; 具体到某个仓库该定多少, 要拿它自己的命令实测一遍(改一个文件到看到结果要几秒) 再定. 定之前先问: 超过几秒之后, 这个仓库的人真的会开始 `--no-verify`?

## Agent hook 的工程细节

- **统一协议**: 从 stdin 读一个 JSON, 用退出码或 JSON 输出表达决策. 这样同一份 hook 脚本能在Claude Code / Codex / 其它 runtime 注册, 不用为每个 runtime 重写
- **退出码语义**(最容易出错的地方)
  - `0` 放行
  - `2` 阻塞, 并把 stderr 回灌给模型. PreToolUse 阻止这次调用; PostToolUse 让模型看到错误去修
    Stop 让模型继续工作
  - **其它非零码 = 非阻塞错误**  脚本路径写错、解释器不对、语法错误全落到这里
    也就是说 **hook 静默失效的表现和"没发现问题"完全一样**。所以每个 hook 必须有冒烟测试:
    命中时拦截、正常时放行、报错文本里带修复建议。
- **Stop 防死循环**: 输入里 `stop_hook_active` 为真时直接放行; 需要的话在临时文件里计重试次数
- **能内置就不 hook**: 能用 settings 的 permission `deny` 表达的规则优先用它  内置控制比 hook 更难绕过. hook 适合表达"要看内容才能判断"的规则
- **防篡改**: hook 脚本、settings、CI 配置本身属于**受保护路径**  改它们的改动要有人审批, 否则红线可以被任何一次提交悄悄拆掉

## 按路径分流(lane)

Stop 阶段付不起全量检查, 所以按"这一轮改了哪些路径"选一条 lane 跑

- 前缀表比 glob 好: 判据要能在人脑里一眼算出来, 也要能在 git 失败时安全退化
- **兜底一律偏向"照常跑"**
  - 算不出变更集(git 失败)→ 跑整条 lane, 宁可慢不可漏
  - 路径没被任何 lane 认领 → **不跳过**, 照常跑并提示登记
- **分流表本身要被机器校验**: 仓库里每个顶层条目都必须被某条 lane 或一份豁免名单认领. 漏掉一类路径的症状是"改了东西却一条门禁都不跑", 而这在 hook 运行时**完全看不出来** (不报错、不输出). 这是分流设计里唯一必须自动化的一环

## CI

- **路径分流 + 并行 lane**: static / 类型 / 单元 / 集成 / 契约 / e2e / 元门禁 各自成 job
- **聚合 job**: 所有 lane 作为 `needs`, 分支保护只要求这一个聚合项. 这样增删 job 不用改分支规则
- **失败信息可操作**: 直接打印修复命令, 而不是让模型去猜
- **上传产物**: 测试报告、截图、覆盖率, 并在 PR 里贴链接  人和 agent 都要能看到证据
- **CI 时长是 agent 回路的一部分**: 超过 15 分钟, 长任务会大量空等. 用缓存、分片、路径分流压时长
- **禁用 `continue-on-error` 掩盖失败**; 重型的、只在主干跑的检查放独立 workflow, 不污染 PR 面板

## 节奏调整 vs 放松

为了在 Stop 阶段跑得动, 常常需要一个"加快档"(例如关掉覆盖率采集). 它必须是

- **显式写在命令行上的 flag**, 不是环境变量  环境变量会让同一条命令的含义取决于调用者, 而 CI 与 pre-push 跑的正是同一条命令, 那等于把"门禁定义只有一份"劈成两半
- **只关掉"可选的那部分采集", 不是关掉门禁**: 依赖该数据的门禁应当按声明自动跳过并打印原因, 严格路径仍由 push 与 CI 守住
- **在注册表里看得见**: 一个必须写在命令行上的 flag 在 diff 里是可见的
