# 本地质量契约

这一阶段只处理开发机到推送前: 格式、注释、静态分析、类型、测试、生成物、架构、pre-commit、pre-push 与 agent hook. 继承目标项目已有约束; 技术栈命中 Python 时, **必须**读 impl/python-standards.md 并逐项核对, 不能因为失败史里没出现就跳过用户规定的代码标准

## 一条红线的完成条件

- 判据: 指定扫描范围、计算方法、违规输出和退出码; 文档声明本身不算判据
- 检查点: 找出实际接线(编辑后、提交前、推送前、CI), 跑过一次真实调用, 不以配置文件存在代替验证. 已有宿主门禁优先复用
- 自证: 临时目录的违规组须 FAIL、合规组须 PASS; 接线本身也要证明不会被静默摘掉. 存量以逐文件基线或带上限的例外登记, 不因老债直接全仓红

判据、检查点、自证齐备才称"已生效"; 否则分别写成文字标准、待接线或待自证. 新检查必须能覆盖扫描根以便测试; 如果宿主现成工具不支持隔离输入, 记录替代测试方案及其盲区. 所有夹具放系统临时目录, 不触碰仓库实际源码

## 工作循环

1. 先取证: 现有配置、hook、脚本、真实运行、失败史及成片违反的书面约定; 把扫描命中与判断分开
2. 逐项审候选模板和宿主现行标准: 标"原样采用 / 按实测调整 / 明确不适用", 写证据与决策人. **项目定制不是省略模板条目**; 用户指定的硬标准优先于统计分位数
3. 选最少的高价值改动: 候选写"问题证据、精确判据、检查点、正反探针、测得成本/重估条件"; 同时列出做得好且不动的部分与这轮不装的项目. 没有历史证据的用户硬标准标"规范要求", 不能伪称已有事故
4. 定接线: 优先用现有工具与现有执行入口. 检查确实需要共享调度时才加门禁总线; 检查点由目标项目测得耗时与禁起服务等规则决定
5. 每轮只落一组可独立验证与回滚的改动; 核对扫描覆盖、例外与基线双向对账, 执行正反探针及宿主验证. 再更新全景和相应 Agent Note, 报告生效、未生效与盲区

## 模板分层(路径相对 skill 根)

先读 templates/index.md 的 A/B/C 层次与裁决表契约. 后端项目读 templates/profiles/backend.md  15 条后端候选; 前端项目读 templates/profiles/frontend.md  7 条前端候选; 所有项目读 templates/profiles/shared.md  9 条公共候选. 工具名称是参考, 类型、架构、接口、文档、测试等覆盖面逐项裁决. Python 细则是补充而非替代该清单

常驻 AI 上下文 (入口文档的分层与体量) 是每一次调用都要裁决的必审项, 不是等文档长胖了才想起来: 判据、自带脚本与降级顺序见 templates/context-layers.md, 与 REF-26 的字节预算一起裁决

具体落地从 templates/skeletons/02-check.md 的单判据骨架和 templates/skeletons/03-probes.md 的正反验证开始; 其余骨架依 templates/index.md 选择. 分流必读 templates/skeletons/07-lanes.md: 混合变更取所有命中 lane 的并集, 共享契约改动覆盖前后端; 未知路径保守执行, 目录覆盖必须有机器校验

## 按需实现

- impl/python-standards.md  Python 项目必读: 300 行、注释与参数一致、函数变更、模块头导入的候选硬标准及例外
- impl/gate-catalog.md  选型时读: 静态类型、架构、文档上下文、棘轮、快照、接线、元门禁的适用性及阈值
- impl/checkpoints.md  定检查点时读: 本地 agent hook、pre-commit、pre-push 与 CI 成本分层
- impl/gate-bus.md  已有多条规则需要统一调度时读: 注册表、执行与失败传播
- impl/self-defense.md  出现白名单、棘轮、元门禁时读: 指纹、探针、控制组与静默失效

产物: 本地质量执行链路、模板逐项裁决表、选中与不装的规则及其证据. 通过条件: 每条宣称落地的规则均有违规 FAIL、合规 PASS 与真实入口证明; 无法机械化的注释语义检查标人工评审, 不冒充自动门禁
