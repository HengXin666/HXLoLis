# 常驻 AI 上下文: 分层与体量

入口文档 (`AGENTS.md` / `CLAUDE.md`) 是每轮都要付一次、却只在对应目录被读到才生效的注入层. 宿主按项目根到工作目录逐级加载, 读到更深目录时**下一次请求**才纳入 — 所以它是懒加载的, 前提是那些文件真的存在

它有两个反向的失败方向, 都要裁决且都要有判据, 只留一条文字约定等于没有

## 两个方向

- **体量**: 单个入口文档超过预算 -> 宿主先丢弃较宽泛的文件, 规则静默失效, 不报错
- **分层**: 只该被某个子目录读到的规则堆在根 -> 每次改动都付它的成本, 而子目录没有规则可读

体量与分层是一对反作用力: 前者是文件太长, 后者是文件该拆没拆. 只做体量, 结果是根文档删到 3000 字节仍然全是全局无关内容; 只做分层, 结果是子目录文档各自长成新的巨物

## 判据

`scripts/check-context-layers.ts` 一次管两个方向, 它是本 skill 自带的脚本, 连同 scripts/report.ts 复制进目标项目即可运行, 无第三方依赖

|检查|判据|默认|
|---|---|---|
|体量|每个入口文档的 UTF-8 字节数|3000|
|覆盖|权重达到阈值的目录必须自带入口文档|15|
|清单|登记与现状双向对账 (可选)|无|
|棘轮|基线登记的缺失目录只在仍然缺失时被容忍 (可选)|无|

权重按**递归**计: 目录下所有源码文件与 `.md` 文档都算, 于是纯文档目录 (如 `docs/`) 与纯代码目录用同一条阈值. 含项目根标记 (`package.json` / `pyproject.toml` / `go.mod` / `Cargo.toml` 等) 的目录无条件要求入口文档, 不看权重

```bash
# 先看现状再定数字: 列出每个候选目录的权重与是否已覆盖
node scripts/check-context-layers.ts --root . --list

# 存量欠账用棘轮, 不因老债全仓红; 阈值与口径按本仓实测改, 不要抄默认值
node scripts/check-context-layers.ts --root . --baseline <基线文件> --min-weight <N> --exclude <前缀>

# 自证: 11 组探针覆盖违规、合规、剪枝、棘轮陈旧项与基线对账
node scripts/check-context-layers.ts --self-test
```

## 红了怎么处置

顺序固定, 与上表两个方向对应

1. **搬走**: 根里只留每个目录都要遵守的规则; 只跟一个子目录有关的, 搬进那个目录的入口文档
2. **压缩**: 删掉模型能自行推导的解释, 别删约束
3. **抬上限**: 说明理由, 会被指纹拦下要求 `--update`

缺入口文档时的动作**不是给每个目录都加一个**. 按权重从高到低处置: 前几个先补, 其余登记进棘轮基线. 基线条目在它不再缺失时必须删除, 否则棘轮会反过来掩盖已经做完的修复

## 与宿主预算的关系

宿主自身有一条总预算 (DSH 默认 65536 字节, 超了先丢宽泛文件). 那条预算只决定**谁被丢弃**, 不决定**内容该在哪一层** — 它不能替代本文件的覆盖判据. 二者叠加时的现象正是最难查的一种: 根文档没超, 但因为同目录还有别的候选文件而被整体省略
