# 代码质量施工

只对**调用时的目标项目**下结论. 先定位项目根、实际代码与正在运行的检查; 逐条写明事实来源、范围和未知项. 不得把本 skill 的类别表当成安装清单, 也不得把本工作区的路径或阈值移植到别的项目. 多个仓库时以用户指定的为准, 否则以当前工作目录所属仓库为准, 子模块分别取证

## 模板入口与建设层次

定方案前必须读 `templates/index.md` 完整前端/后端/公共候选清单、14 类骨架与 A 最小闭环 / B 标准建设 / C 完整覆盖的验收顺序. 按技术栈加载对应模板; 项目适配应产生逐项裁决和实际实现, 不停在审查提纲. 原版 31 项参考规则须覆盖, 缺某一端时明确整组不适用及证据

`assets/source/index.md`  维护或对照原版时读: 四份完整原件、来源哈希及哪些片段只作历史证据. 原件不整篇常驻加载; 施工按 templates 与步骤的适配层执行

## 步骤

|阶段|只做什么|契约|
|---|---|---|
|取证|找现有防线、历史失败和缺口|`steps/1-evidence/index.md`  开始时读, 确定事实与推断的边界|
|本地|分析编辑、提交、推送前能执行的判据|`steps/2-local/index.md`  本地机制需要分析或落地时读|
|远程|分别分析 GitHub 协作文档与工作流|`steps/3-remote/index.md`  项目使用 GitHub 时读; 未使用则标注不适用|
|全景|把现状、缺口、决策和验证汇成可核查文档|`steps/4-portrait/index.md`  每轮都读, 生成项目专属图与证据表|

常驻 AI 上下文 (入口文档 `AGENTS.md` / `CLAUDE.md`) 每一轮调用都要付一次 token, 且只在对应目录被读到才生效. 写进根文档的每一行都在向所有改动收税: 只跟一个子目录有关的规则要放进那个子目录的入口文档, 而不是根级常驻文件. 分层与体量的判据、自带门禁与降级顺序见 `templates/context-layers.md`  它属于每次调用的必审项, 不等到文档长胖了才做

先判任务模式: 全面设计、定点补一条、事故升级、复盘删减. 先取证并逐项裁决候选标准, 再选最少的有效增量; 删除、合并或收窄过时门禁同样是成果. 对规则区分四级强度: 人工纠正、文字规范、确定性检查、让违规无法表达. 每条声称生效的红线必须同时具备**判据 + 检查点 + 自证**; 提案与已接线的门禁分开报告

不照搬别的项目的工具、基线和吞吐预算; 但本 skill 明列的候选标准不可静默省略. 对于用户指定的阈值(例如 Python 每文件 300 行), 先按硬标准核对, 存量用逐文件棘轮过渡, 调整须有理由与用户确认. 确认选型后, 一轮只处理能独立验证和回滚的一组改动; 用违规组 FAIL 与合规组 PASS 验证新判据, 并实测它在声明的检查点被调用

## 决策记录交接

本 skill 真身为何保留候选标准、同时将决策记录交给宿主的决定, 见 `.agents/notes/implemented/process/2026-10-02-code-quality-skill-project-specific-landscape.md`(只在维护本仓 skill 时读取, 面向其他项目时用其自己的决策记录). 编辑模板后运行 `scripts/verify-templates.ts`  验证四份原件、14 类骨架、31 条规则的完整性与索引可达性. 常驻上下文分层判据为何从 C 层提升为必审、以及 REF-26 为何只算做了一半, 见 `.agents/notes/implemented/process/2026-10-06-context-layer-gate-and-ref26-completeness.md`(只在维护本仓 skill 时读取). 编辑本 skill 时运行 `scripts/verify-note-links.ts`  核对本技能与上述两篇 note 的双向引用; 它弥补宿主 `verify-backlinks` 默认排除 `.agents/**` 与 Markdown 的盲区

发现宿主已有决策记录机制时, 加载并遵循宿主机制. 若项目使用 `hx-agent-notes`, 在发生非平凡改动时调用该 skill 处理查找、更新或创建 note、源码锚点、同次提交与门禁; 这里不复制它的实现与生命周期. 全景文档描述代码质量**现状**, Agent Note 记录具体**决策及放弃的选项**, 二者互相引用而不互相代替

首轮输出五件事: 总体判断、已经做得好且保留的部分、证据支持的选型或删减(不足三条就少报)、最多四个需用户裁决的问题、首个增量. 每项候选写明问题、判据、检查点、自证与代价; 列出这轮明确不装什么及原因. 之后每轮只报告生效门禁、正反探针、实际接线、全景更新与剩余缺口

收尾时给出全景文档路径、图、已验证的判据与未覆盖风险. 新建的项目文件必须位于目标项目约定的文档位置; 无约定时用 `docs/code-quality-landscape.md`, 不要把具体项目的产物写回本 skill
## 自带脚本

- `scripts/check-context-layers.ts`  上面那条分层与体量判据的本体. 复制进目标项目后直接运行, 用法与降级顺序见 `templates/context-layers.md`; `--self-test` 给出 11 组正反探针
- `scripts/verify-templates.ts`  本 skill 维护时运行: 核对四份原件哈希、14 类骨架、31 条规则、索引可达性, 并调用 `check-context-layers.ts --self-test` 防它静默失效
- `scripts/verify-note-links.ts`  本 skill 维护时运行: 核对它与决策 note 的双向引用

最后两条只服务于本 skill 自身的防腐, 不随目标项目复制
