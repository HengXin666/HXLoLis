# Agent Note: 否定约束  用户说"不要广告"，我们却优先返回广告

Status: implemented

- 影响: `components/HX-Sagasu/src/recall.ts`（`parseNegation` / `negationPenalty` / `queryTerms` / 层内第四维）
- 上游: 精读 argo `query_understanding.parse_negation`（`query_understanding.py:84`）

## Problem

**实测四条查询，全部失败**（2026-09-18）：

| 查询 | 修复前实测 | 应该的行为 |
|---|---|---|
| `除了百度的搜索引擎` | 检索词含 `除了`/`了百`/`度的` | 排除「百度」，其余照查 |
| `Rust 所有权 -GC` | `gc` 是**必需词** | 排除「GC」 |
| `不要广告的图片压缩工具` | 检索词含 `不要`/`要广` | 排除「广告」 |
| `notion 替代品 NOT 飞书` | `not` 是检索词 | 排除「飞书」 |

**两个方向的错**：

1. **否定触发词本身被当成检索词**。`除了`/`不要`/`not` 这些字**必然出现在查询里**，
   于是任何含这些字的文档都被判为"覆盖了查询词"  覆盖度判据被系统性污染。
2. **被排除的实体被当成必需词**。用户说"不要广告"，我们却把含"广告"的结果排在前面。

**这不是"少接一个引擎"能补的，是查询理解能力缺失。** 而它属于我们该自己长的部分 
argo 的引擎可以借，但"怎么理解用户说的话"不该外包。

## Decision

**实现否定解析，接入两个位置。**

### 一、`parseNegation(query) → { exclude, clean }`

七条模式：中文四条（`除了`/`不想`/`不要`/`排除`）+ 英文两条（`NOT`/`without`）+ 减号前缀。
实体边界在 `的/，/空白/结束` 处收边，不超过 20 字。

**减号那条必须排除"负号前是字母数字"的情形**  否则 `gpt-4` 会被解析成"排除 4"。
实测 `gpt-4 提示词` 与 `GPT-4o 生图` 都**不受影响**。

### 二、`queryTerms` 改用 `clean` 抽词

检索词从剔除否定片段后的查询里抽。**排除词不进检索词**，但也不被丢弃。

### 三、`negationPenalty` 接入层内排序作**第四维**

命中里出现排除词 → 降档。**只降档不丢弃。**

## Alternatives considered

- **把排除词从查询里删掉就完事**：一行改动，最省事。否决理由：那样 `不要广告的图片压缩工具` 会退化成 `图片压缩工具`，而**"不含广告"这个约束丢失了**  用户明确表达的意图被静默丢掉。排除词必须参与排序。
- **命中排除词就丢弃**：语义最"干净"。否决理由：**"含该词"未必等于"是关于它"**。一篇《广告之外：图片压缩工具横评》含"广告"却是好结果。丢弃会误杀，而降档保留了它。测试显式锁住"含排除词的那条仍然保留"。
- **把否定解析做成独立模块 `src/negation.ts`**：文件更小更清晰。否决理由：`queryTerms` 与排序都在 `recall.ts` 里，而**否定解析必须与它们共用同一份规则**（否则口径漂移这正是第 18 轮"检索侧用 bigram、判定侧不用"那个 bug 的形态）。放在同一文件里，改一处不会漏另一处。
- **照搬 argo 的正则**：它有实测支撑。否决理由：**它的实体边界只处理了"后面跟 `的/，/空白`"的情形**，漏掉"查询末尾无标点"（`notion 替代品 NOT 飞书` 的 `飞书` 在末尾）。另外它的正则里 `\u4e00-\u9fff` 直接写成字符区间，在中英混排下边界判断更脆。**形态借鉴，规则自己写。**
- **不做，等以后有语义模型再说**：否定是"语义"问题，正则做不干净。否决理由：**实测这四条查询的失败是 100% 的，而正则能修掉其中全部**。等语义模型意味着在此之前每一条带否定的查询都是坏的。**能做对的部分先做对。**
- **同时实现 argo 的地域解析**（`parse_geo`，含 100 个城市词典）：它确实也是我们缺的。**本轮没做**  地域解析的价值依赖"有没有地理类来源可路由"，而我们目前**没有一个地理源**。先做否定，因为它的收益立刻可见（每条带否定的查询都受影响）。

## Consequences

- **层内排序现在是四维**：相关性档 → 来源契合档 → 证据块密度档 → 否定约束档。**每一维都是稳定分档**，同档内保持原序。
- **`queryTerms` 的口径变了**：带否定的查询，其检索词集合会变小（垃圾词消失）。这会**同时影响**排序（`isQueryRelevant`）与充分性（`queryCoverageSignal`） 两处共用这一个函数，口径不允许漂移。
- **未做**：地域解析（`parse_geo`）、多意图拆分（`split_multi_intent`）。前者缺地理源，后者缺多路召回。
