# Agent Note: 对话语义层以「原文保真 + 推断必标记」为不可退让的契约

Status: implemented

Decision-ID: conversation-semantics-contract


## Code

- `components/HX-Sagasu/src/types.ts`
- `components/HX-Sagasu/tests/sink.test.ts`

## Problem

HX-Sagasu 的目标要求在"对话式（论坛）语义中做精确理解：错别字容错、帖子-回复结构、引用链、多轮上下文"。现状是**这一层完全不存在**：argo 只有单轮 query 字符串与 `--input-kind` 判定，其社会检索只做跨平台**标题级**话题提取（`social_research.py`），不保留任何回复关系。

从零建这一层时，有三个决策点天然容易走反，且走反了在后来的"简化"里不会被发现：

1. **归一化该不该覆盖原文。** 归一最自然的实现就是就地替换文本。但这样一来，引用出去的就是归一后的文本用户拿它去核对会发现"论坛里没有这句话"，证据链断裂。
2. **推断出来的引用链要不要标记。** 平台大多不提供引用关系。推断能让数据看起来更完整，而"看起来完整"会诱使把推断结果当事实写进结构。
3. **"楼上说的那个"该不该猜。** 在没有阅读游标时，"楼上"没有确定含义。猜一个候选能让接口永远有返回，代价是把 A 的话安到 B 头上。

## Decision

**两条契约 + 一条边界，全部用可执行测试钉死。**

1. **原文保真**：`Turn.text` 是证据，永远逐字保留；`Turn.normalizedText` 是索引，只供检索。两者不互相覆盖。`digest()` 产出的引用取 `text` 而不是 `normalizedText`。
2. **推断必标记**：平台给了 `quotedTurnId` 就是事实；推断出来的必须同时置 `quoteInferred: true`。同理，归一化的每一处改动都进 `edits[]`（规则名 + 位置 + 前后文），可逐条审计。
3. **边界**：本层只做**结构性**工作（把"楼主/楼上/他"解析到参与者与楼层，按时间取回原文）；**不**判断"到底改没改口"那是上层 Agent 的判断。指代不明确时返回 `ambiguous` 候选而不是猜一个。

配套的量化判据（对齐"下结论前必须做消融对比"）：
- `消融对比` 测试实测归一前后的重合度提升，把"更准"变成可测量的数字；
- `单个错字不足以判定不相关` 测试锁死"不能因为一个错字就判不相关"。

## Alternatives considered

**什么都不做 / 复用现有。** 最强理由是无需新增实现和维护成本. 现有状态仍存在 Problem 中的具体缺口, 因此采用本记录的选择

- **归一化就地覆盖原文（`text = normalized`）**：实现最简单，且下游只需读一个字段。否决理由：证据一旦被改写就不可核查引用出去的句子在源站上不存在，整条"可核查"承诺作废。这个代价在功能测试里看不出来，只在"用户拿引用去核对"时爆。
- **引用链推断结果不标记，直接当事实写入**：数据更完整、下游更省事。否决理由：推断规则（重叠 + 距离）必然有假阳性；一旦与真引用混在一起，就没有任何下游能区分，而"把 A 的话安到 B 头上"是会改变结论的错误类型。标记的代价只是一个可选字段。
- **"楼上"无游标时取"倒数第二楼"作为兜底**：接口永远有返回，用户体验"顺滑"。否决理由：这是猜，且猜错的概率不低（用户可能在看任意一楼）。返回 `ambiguous` + 候选是更诚实的失败，也让调用方有机会补 `cursorTurnId`。
- **第三人称按"最后发言的人"解析**：实现一行搞定。否决理由：最后发言的人往往只是最后一个水贴的，而**被引用最多**的人才通常是话题中心。"引用入度"多花几行但判据更站得住。
- **做叠字折叠（"非非常"→"非常"）**：看起来是纯收益的口语清理。**实测否决**：正则 `([\u4e00-\u9fa5])\1` 无法区分"非非"与"人人"，会把正常叠词折坏（测试当场抓到 `人人都能用的工具` → `人都能用的工具`）。要做得对必须有词表，属未来工作；当前刻意不做，并用 `已知边界` 测试锁死这个行为。

## Consequences

- 下游（索引、引用、证据卡）必须**显式选择**读 `text` 还是 `normalizedText`多一个字段的代价，换来证据链不断。
- `normalizedText` 与 `text` 都要存，存储翻倍（对文本量级可接受）。
- 引用链推断只在"引擎已知"时产出真值，其余带 `inferred`；下游聚合引用关系时必须决定如何使用这一字段，不能假装它不存在。
- 叠字规则缺席：口语里的"非非常"不会被折成"非常"。**已知边界，非缺陷**，由测试锁定，避免后人以为是漏做又加回那条有误伤的正则。
- 归一化词表（`CONFUSIONS`）是硬编码的，会随领域增长而需要维护；它只收**多字词**单字改写歧义过大，收益不抵风险。

## Verification

- `bash components/HX-Sagasu/scripts/test.sh` → **20 tests / 20 pass / 0 fail**（Node 内置 test runner + 原生 TS，零依赖零构建）；
- 三条验收判据各有对应测试：`端到端场景: 「楼主后来改口了吗」能回到具体楼层原文`（架构方案 §5.2 判据 #1）、`消融对比`（判据 #2）、`引用产出的是**原文**…` 与 `「楼上」…报歧义`（判据 #3）；
- 归一化的两个真 bug 由测试抓到并修掉：自我更正标记后残留的"是"、句首填充词过度删除（`就是那个那个我们…` → 曾错误产出 `就是我们要…`）；
- 测试刻意保留一条**锁死当前行为**的用例（`已知边界: 叠字不被折叠`），把"做不到"与"没做"区分开。
