# Agent Note: 分层召回以「层序即优先级 + 失败不计入供给」为契约

Status: implemented

- 影响: `components/HX-Sagasu/src/{recall,authoritative}.ts`

## Problem

用户明确要求"先聚合各大权威平台，然后才是搜索引擎"。此前系统里根本没有"权威"这个概念所有来源平铺在一个结果列表里，靠一个分数排序。要把它变成结构而不是口号，有三个决策点：

1. **权威性怎么定义。** 最省事的做法是维护一张"哪些站权威"的名单。但名单会腐烂，而且"某某网站很权威"不是一个能被执行、能被反驳的判断。
2. **什么时候停止下降。** "拿到 N 条就够"是唯一能让分层不无限展开的规则，但这里的 N 必须同时说清"哪一层给的"和"是真给了还是报错了"。
3. **不同来源的分值要不要融合。** 融合看起来能让排序"更科学"。

同时有三个失效模式必须在结构上封死：

- **把失败当空**。若权威层全部报错却按"0 条结果"处理，系统会安静地降级到搜索引擎，而用户以为自己看的是权威来源。
- **降级不可见**。若最终结果不标注实际到达了哪一层，调用方无法区分"权威来源确认过且够用"与"权威来源全挂了，这是兜底"。
- **空结果的无限下降**。0 条命中永远不构成"充分"。

## Decision

**第 0 层 = 带持久标识符的开放数据接口；充分性只统计成功返回；层序即优先级，不融合分值。**

1. **权威性定义为"机构责任 + 持久标识符"**：Crossref 的 DOI 可解析回出版方、PubMed 的 PMID 可查、arXiv 有稳定 ID、GitHub 仓库有 owner 与提交历史。每条 `SourceDescriptor` 必须带 `rationale`，测试强制第 0 层来源的理由里出现可验证的身份概念（DOI/PMID/arXiv/owner/登记机构/存档/编辑审核），且必须真的有实现。
   - **与"搜到某个官网"的根本差别**：搜索引擎返回的是一个 URL，谁都能声称自己是官网；这一层返回的是带标识符的实体，**同一性由标识符保证，不由页面内容保证**。
2. **充分性只统计成功返回的命中**（`AUTHORITATIVE_FIRST`）：`successfulTiers` 只收"至少有一个来源成功返回"的层。全部报错的层不算提供了供给，因此不会满足停止条件必须继续下降。
3. **层序即优先级，不做跨来源分值融合**：不同来源的分值不可比（Crossref 无分值、GitHub 的 star 数、搜索引擎的相关度），把它们塞进一个数里会让"权威优先"悄悄变成"分高优先"。层内保持来源给出的相对顺序。
4. **每次召回都产出完整的 `tiers[]`（含被跳过的层及其原因）+ `reachedTier`**这是"分层可审计"的载体，调用方能一眼看出"这是权威确认的结果"还是"兜底搜索的结果"。

第 0 层实测可用的 7 个接口（全部无需凭证）：crossref / arxiv / github / wikipedia / hackernews / pubmed / openalex。

## Alternatives considered

- **维护一张"权威网站白名单"，用域名匹配**：实现最简单，且能覆盖任意站点。否决理由：域名白名单是一个**无法执行、无法反驳**的判断它不告诉任何人"这条证据凭什么信"。而且它会腐烂（站点改版、被收购、内容质量变化）却没有任何机制发现。用持久标识符则相反：标识符本身就是可验证的，且验证动作在**外部系统**里（DOI 解析、PMID 查询），不依赖我们的判断。
- **把不相关的权威源也登记进第 0 层**（"某网站在现实里很权威就放进去"）：看起来覆盖率更高。否决理由：充分性判断基于**供给**。登记一个取不到数据的来源，会让"第 0 层返回了 3 条"这个判断建立在幽灵之上；更糟的是它会让报告里的"权威层覆盖"数字失真。
- **所有来源的 score 融合成一个排序分**：能让排序看起来"更科学"，也便于统一截断。否决理由：跨来源分值不可比。B站的播放量、GitHub 的 star、arXiv 的无关度、搜索引擎的相关度之间没有换算关系；一旦融合，"权威优先"就退化成"分高优先"，而这正是本层要防的。
- **第 0 层用一个真实网络测试来验证适配器**：更"真实"。**实测否决**：权威接口的响应体很大（Crossref 单页可达数十 KB），不适合放进仓库夹具；而且离线测试根本不需要网络。改用**采集真实响应作夹具**（`tests/fixtures/{crossref.json,arxiv.xml,github.json,…}`，2026-09-16 从线上采集）解析逻辑仍然对着真实数据验证，但测试可离线重放。**这个选择的代价必须写下来**：夹具验证的是**解析**，不验证端到端可用性。因此回归套件无法发现"接口下线/改签名/改版"这类失效，那只能靠 `tests/fixtures` 的重新采集。这是一个**已知的能力缺口**，不是遗漏。
- **充分性规则写成"命中数 ≥ N 就停"（不看层级）**：更简单，也不会在权威层为空时反复下降。否决理由：这会让"权威优先"完全失去意义搜索引擎在第 2 层，它的命中数通常远大于权威层，结果永远是搜索引擎赢。
- **降级时抛出异常**（"权威层挂了"）：最响亮。否决理由：降级到搜索引擎是**合法**的兜底行为，用户要的是答案。抛错会把这个合法路径变成失败。正确的做法是**给出答案同时标明它的来源层级**`reachedTier` 与 `failures` 一起说明"这是兜底，不是权威确认"。

## Consequences

- 第 0 层的供给质量直接决定"权威优先"是否成立。当前 7 个来源里，学术类（Crossref/arXiv/PubMed/OpenAlex）占 4 个**对非学术问题，第 0 层的相关性会明显偏弱**（实测：查询 "Rust 所有权" 的首条是 Crossref 上一篇中文自然资源论文）。这是真实的短板，靠 GitHub/Wikipedia/HN 缓解但不足以解决；补中文技术社区的一手来源（官方文档站、RFC 仓库、厂商公告）是后续工作。
- `SourceFetcher` 的失败契约与适配器层一致：取不到就抛错。因此新增来源时必须遵守，否则"失败当空"会从新的入口重新进来。
- PubMed 只做 esearch（拿 id），标题就是 id 本身。**刻意不编造标题**猜出来的论文名会成为假证据；补齐标题需要第二次请求，属后续工作。
- `recall.exhausted` 表示"没有因为够了而提前停"，与"有没有结果"无关。调用方必须自己看 `hits.length`系统不替它编造"找到了"。
- 层级归属是硬编码的表。新增来源要显式决定它属于哪一层并写出理由，测试会挡住没有理由的条目。

## Verification

- `bash components/HX-Sagasu/scripts/test.sh` → **88 tests / 88 pass / 0 fail**；
- 三个失效模式各有测试：`权威层全部报错不算供给`、`降级必须可见（reachedTier=2）`、`0 条命中不构成充分但下降终止`；
- **线上端到端实测**（非夹具）：查询 "transformer" → 到达层级 **0**、7 个来源全成功、21 条命中、**标识符覆盖 21/21**、第 1/2 层被跳过且写明原因；查询 "Rust 所有权" → 同样停在第 0 层，15 条命中、标识符覆盖 15/15；
- 权威性定义有测试强制：第 0 层每个来源的 rationale 必须包含可验证身份概念，且必须有实现（`声明与实现不允许脱节`）；
- 失败契约有测试：HTTP 503 → `http`、坏 JSON → `parse`、socket 异常 → `network`；空结果是合法结果且与失败严格区分；
- OpenAlex 的 `mailto` 约束有测试（不带会 429，这是实测结论）。
