# Agent Note: 移植而非 fork  复用 argo 的三件具体实现

Status: implemented

Decision-ID: port-not-fork

- 上游: **argo v2.8.6（MIT License © 2026 taxueseek）** 的 `scripts/url_safety.py` 与 `scripts/readability_extract.py`

## Code

- `components/HX-Sagasu/src/url-safety.ts`

## Problem

用户问：**"为什么你不是 fork 然后拓展呢？既然它更好。为什么不用"**

**这个质疑成立，而且暴露了我的一个疏漏：我从来没检查过 argo 的许可。**
实测它是 **MIT**  可以自由 fork、修改、再发布。而我此前花了两轮时间在外围
**重写它的算法**（`evidenceBlocksOf`、`parseNegation`、`relaxSteps`），
其中至少 `evidenceBlocksOf` 是**可以直接用的**。

## Decision

**不 fork 整个项目，但移植它的具体模块。**

### 为什么不全盘 fork

| | HX-Sagasu | argo |
|---|---|---|
| 语言 | TypeScript | Python 3.14 |
| 依赖 | **零依赖零构建** | pyyaml（+ 可选 curl_cffi） |
| 规模 | 14 个文件 | **91 个文件 / 38005 行** |

Fork 意味着在 Python 里维护我们的分层召回、账本、证据契约，或者把 38005 行移植过来 
**两条路都要放弃"零依赖零构建"**，而那是本仓库的硬约束（没有 `package.json`）。

更要紧的是：**fork 会把两边的差异变成我的维护负担**。argo 的 140 个引擎、反爬、
缓存  它维护得比我好，因为它有 65k stars 的使用量在压。我 fork 之后它每次更新
我都要 merge，而我的改动（分层、证据契约、失败语义）都在它没有的维度上。

### 分界线

| 层 | 谁维护 | 理由 |
|---|---|---|
| 引擎接入 / 反爬 / 抓取降级 / SSRF | **用 argo 的**（MCP 或移植） | 它做得比我能做的好，且有使用量在压 |
| 查询理解 / 排序 / 证据契约 / 分层 | **我们自己** | 这些是它的**弱点**（域名白名单、`safe_search` 吞异常、伪交叉验证） |

### 本轮移植的两件

**一、`url-safety.ts`（移植 `url_safety.py`，229 行 → 约 300 行 TS）**

SSRF 防护。选它先做的理由：**这是安全边界，错了代价最大**，而它的完整度远超体积。
逐条保留的判定：

1. scheme 白名单（仅 http/https）
2. 主机名黑名单（localhost、**裸单标签主机**、`.local`/`.internal`/`.lan` 等）
3. DNS 解析后 IP 段检查（IPv4 14 段 + IPv6 7 段）
4. **数字字面量规范化**（`0177.0.0.1` 八进制 / `0x7f.0.0.1` 十六进制 / `2130706433` 单段整数）
5. **IPv4-mapped IPv6 转回 IPv4**（`::ffff:127.0.0.1` 不转换就能绕过）
6. **DNS 解析失败 → 保守拦截**
7. **fake-ip 例外**（Clash/Surge TUN 占位段）

**二、`readability.ts`（移植 `readability_extract.py`，239 行 → 约 250 行 TS）**

正文提取。选它的理由：子代理明确指出它"纯 stdlib、公式可解释、毫秒级"，
而**我们完全没有正文提取能力**（只有 snippet）。

逐条保留的算法与细节：

- 密度评分 `(chars - 2×linkChars) / (chars+1)` × 密度惩罚 × 标签权重
- **容器归并保持文档顺序**（argo 注释明确记着旧版 sort-by-density 会把页脚插进正文中间）
- **`td` 短块下限是 2 而不是 30**（表格是原子数据单元，30 会丢光整张表）
- **标题下限 6 且不参与短块降权**
- **容器清空只在"容器内没产出任何正文块"时发生**

## Alternatives considered

- **全盘 fork argo**：许可允许，且能立刻拿到 140 个引擎 + 反爬 + 缓存 + 熔断。否决理由：**语言栈与规模都不匹配**（Python 38005 行 vs TypeScript 零依赖 14 文件），fork 后要么放弃零依赖，要么把两边的差异变成长期 merge 负担。而且**它的弱点（域名白名单权威分、`safe_search` 吞异常）正是我们要改的地方**  fork 之后每次上游更新都要重新应用这些改动。
- **继续在外围重写它的算法**（我前两轮的做法）：不用处理语言差异。否决理由：**这是重复劳动**。`url_safety` 的 SSRF 完整度（数字字面量规范化、fake-ip 例外）是我自己想不到的  那些来自 argo 的真实使用反馈。**重写只会得到一个更差的版本。**
- **把移植的代码标注成"参考 argo"而不写清许可**：省事。否决理由：**MIT 要求保留版权声明**。两个文件的头部都写明了来源、版本、许可与作者。这不是形式主义  没有它，下一个人无法判断这段代码能不能改、能不能商用。
- **移植时"顺手改进"**（比如把 `MIN_DENSITY` 调成更符合直觉的值）：看起来更专业。否决理由：**那些常数是 argo 调过的**，我没有它的测试语料来验证改动。**移植的第一原则是忠实**  要改也得先有能证伪的实测。本轮只做了一处必要适配：Node 没有 `ipaddress` 与 `html.parser`，自己实现了 CIDR 匹配与最小 HTML 分词器。
- **不移植 `content_security.py`（提示注入防护）**：它是子代理点名的"最值得复用的三件"之一。**本轮没做**  它 31.7K、8 个语系约 80 条正则，是一份独立工作量。列为下一步。
- **把移植的模块接进 recall 主流程**：让它们立刻产生价值。**本轮没做**  两者都需要新的调用场景（`url-safety` 需要"抓取任意 URL"的入口，`readability` 需要"从 URL 取正文"的路径），而**我们目前没有这个入口**。先有正确的实现，再有入口，顺序不能反。

## Consequences

- **两个新模块都是纯函数**，不碰网络（`url-safety` 的 DNS 解析通过 `Resolver` 参数注入，测试可替换）。
- **`url-safety.ts` 的 CIDR 匹配是自己实现的**（Node 无内置）：IPv4 折 32 位整数、IPv6 折 128 位 BigInt 再比前缀。**刻意不用字符串前缀匹配**  那对 `10.0.0.0/8` 恰好能用，但对 `100.64.0.0/10` 这类非 8 倍数边界会算错（测试显式覆盖了 `/10` 与 `/12` 的上下边界）。
- **`readability.ts` 自带最小 HTML 分词器**：只产出标签事件与文本，不需要属性。刻意处理了 raw text 元素（`script`/`style` 内容里的 `<` 不许当标签）与自闭合标签（不让深度计数失衡）。
- **未接入任何调用方**  见上。

## Verification

- `bash components/HX-Sagasu/scripts/test.sh` → **217 tests / 217 pass / 0 fail**（新增 18 条）
- **SSRF 测试覆盖 9 种真实绕过手法**：八进制环回、十六进制环回、单段整数、IPv4-mapped IPv6、localhost、云元数据端点 `169.254.169.254`、CGNAT、`::1`、`fc00::`
- **CIDR 边界测试**：`100.64.0.0/10` 与 `172.16.0.0/12` 的上下边界各测一条（字符串前缀匹配会在这里算错）
- **fake-ip 测试**：全占位段放行、**含任一真实私有 IP 仍拦截**
- **正文提取测试**：文档顺序（页脚不许插中间）、`td` 表格数据不许丢、`script` 内容不许泄漏、实体解码、自闭合标签
