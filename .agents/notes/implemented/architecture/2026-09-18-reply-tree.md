# Agent Note: 回复树  把"这句话在回谁"从平铺里捞出来

Status: implemented

Decision-ID: reply-tree


## Code

- `components/HX-Sagasu/scripts/serve.ts`
- `components/HX-Sagasu/src/reply-tree.ts`

## Problem

`thread.ts` 一直在建回复关系（`parentId` 与 `quotedTurnId`，且区分"平台给的"与
"推断的"并标 `quoteInferred`） **但没有任何地方呈现它**。

实测（B站 `BV1GJ411x7h7`，11 楼）：

```
有 parentId: 8 | 有 quotedTurnId: 8 | 推断出来的引用: 0
```

**8 条有完整关系，且没有一条是猜的**  平台直接给了事实。
而 CLI 与界面都按**楼层顺序平铺**。

**平铺会丢掉的正是引用链的价值**：第 4 楼回的是第 1 楼还是第 2 楼，
在平铺视图里完全看不出。

## Decision

**`buildReplyTree` + 默认显示树（CLI），`--flat` 保留平铺。**

### 引用与父级是两回事（实测发现的）

实测 `#10 老咸鱼A` 的**父亲是 #7，而它引用的是 #9**。

```
#7 老咸鱼A      坏消息：被骗了 好消息：真好听
  └ #9 -Megumin_     坏消息:好消息 好消息:坏消息
  └ #10 老咸鱼A        回复 @惠惠Megumi_ :相 对 论 → 引用 #9
```

- **父**（`parentId`）= 挂在哪条下面（帖子结构）
- **引用**（`quotedTurnId`）= 引用了谁的话（那条 `回复 @某人` 指向的对象）

**只看父子会以为 #10 在回 #7；只说引用会丢掉树形。两者都显示。**

### 三条实现约束

1. **孤儿挂到根，不丢弃**。父可能被删、被截断、或被平台给错 
   而"这条回复存在"是事实。丢掉会让帖子结构看起来比实际少一层。
2. **推断的引用必须标出来**（`quoteInferred`）。不假装是事实。
3. **深度用迭代算**，不用递归  2000 层链的测试锁住了这一点。

## Alternatives considered

**什么都不做 / 复用现有。** 最强理由是无需新增实现和维护成本. 现有状态仍存在 Problem 中的具体缺口, 因此采用本记录的选择

- **继续平铺，不做树**：省掉一个模块。**否决理由**：**平铺丢的正是引用链的价值**。目标第 (3) 项明确要求"帖子-回复结构"与"引用链" 数据一直在，只是没有承载物。**这与本项目反复出现的"机制在、没呈现"是同一形态**。
- **只显示引用（`quotedTurnId`），不建父子树**：引用是"回复 @某人"的更精确版本。**否决理由**：**引用是点状的，树是结构性的**。一个引用回答"这条在回哪一条"，但看不出"这一支讨论从哪长出来、有几条分支"。实测 3 个根节点（三个话题分支） 那是只有树才能看出的东西。
- **只显示父子，不标引用**（第一版的做法）：实现更简单，且树形已经够用。**否决理由**：**实测 `#10` 的父亲与引用不同**。不标引用会让人以为它在回 #7，而它实际在回 #9 说的话  **那是给用户一个错误的阅读指引**。
- **默认平铺，`--tree` 才显示树**：更保守，不改变既有输出。**否决理由**：**默认应该是信息量更大的那个**。平铺不省任何东西（都要遍历），而树多给了结构。改默认值有代价（依赖旧输出的人会受影响），但**这里没有别的人**，且 CLI 尚未被任何自动化依赖。
- **把树渲染成 JSON 而不是缩进文本**：机器可读。**否决理由**：**CLI 是给人看的**（`--json` 已有整份原始输出）。缩进文本用 `└` 与缩进表达深度，一眼能看出结构  这正是终端擅长的。
- **在界面上画图形化的树**（SVG/DOM 嵌套）：更直观。**本轮没做**  界面的 `/api/thread` **已经返回了边表**（`edges`），前端可以直接用；但画树需要独立的交互设计（折叠、跳转），属单独的界面工作。

## Consequences

- **CLI 的 `thread` 默认输出回复树**（`--flat` 回到平铺）。
- **`/api/thread` 返回 `tree.edges`**（`from`/`to`/`quoted`/`inferred`），前端可用它画树。
- **第 (3) 项的"帖子-回复结构"现在有了呈现物**  此前只有数据没有视图。
- **仍未做**：界面上的图形化树（见上）。
