# Agent Note: 对话语义的第一个真实入口  以及我凭印象写错的三个字段名

Status: implemented

- 影响: `components/HX-Sagasu/scripts/sagasu.ts`（新增 `thread` 子命令）
- 相关: `src/resolve.ts`（实现未变，此前**零调用方**）、`src/thread.ts`、`src/adapters/*`

## Problem

目标第 (3) 项要求"在对话式/论坛语义下做精确意图理解（错别字容错、帖子-回复结构、
引用链、多轮上下文）"。

**这条链的每一环都写好了、都有测试，但没有一条路能走完**：

| 环节 | 实现 | 此前有调用方吗 |
|---|---|---|
| 取回原始帖子结构 | `adapters/bilibili.ts` `thread(ref)` | ✅ 有（测试） |
| L1 归一（错别字/繁简/全半角） | `thread.ts` `normalizeThread` | ❌ 仅测试 |
| L2 指代消解（"楼主"/"楼上"） | `resolve.ts` `resolve` | ❌ **零调用方** |
| 引用链产出 | `resolve.ts` `relevantFloors` | ❌ 零调用方 |

**`resolve.ts` 此前零调用方**  而它的核心场景实测是能用的。这与 CLI 本身存在的
理由一模一样：**每个模块都被测试证明了"能用"，而没有人能真的用它一次。**

## Decision

**给 CLI 加 `thread` 子命令：拿一个帖子，问一个问题，得到可追溯的引用链。**

```
sagasu thread bilibili:BV1GJ411x7h7 --ask "楼主后来改口了吗"
```

**引用格式必须是 `<平台>:<id>`，不做"从查询里猜帖子引用"**：猜错会**静默拿到别人的
帖子**，而那是隐私边界，不是相关性判断能兜住的。

## Problem（第二个，关于我自己）

CLI 第一版我用**凭印象的字段名**写显示层，实测三个全错：

| 我写的 | 实际 | 症状 |
|---|---|---|
| `t.floor` | `t.id` | 楼层显示 `#undefined` |
| `t.author`（当字符串） | `{ id, name }` | 作者显示 `[object Object]` |
| `res.targets[].turns` | 我用了 `relevantFloors` | **引用链引用了错的人** |

第三条最严重：问"楼主后来改口了吗"，`relevantFloors` 按"话题词重叠"排，
引用了**两条与该问题无关的路人发言**，而**楼主本人的两条发言一次都没出现**。

**而 `resolve` 早就把楼主正确解析出来了**  `role: 'op'`、
`participantName: '老咸鱼A'`、`reason: "提问含楼主类角色词，且该线程有 isOp 标记"`、
`confidence: 1`。

> **我绕过了正确答案，去用一个更弱的判据。**

修后实测：

```
指代: op = 老咸鱼A  依据: 提问含楼主类角色词，且该线程有 isOp 标记  conf=1
  #r376080139 坏消息：被骗了 好消息：真好听
  #r406636358 回复 @惠惠Megumi_ :相 对 论
话题词: "改口了"
```

**为什么 `relevantFloors` 还在输出**：它是有用的**另一个判据**（字面话题重叠），
标签明确写成"**不是**指代目标，只是字面相关"。两者语义不同，混用就会引用错人。

## Alternatives considered

- **不做 CLI 入口，留给将来的 API**：省掉一个子命令。否决理由：**"没有真实入口"是本组件已经栽过两次的病**（`resolve` 核心场景坏了 16 轮、`loadOrRebuild` 零调用方）。API 是"将来"，而**能跑一次是现在**。
- **让 CLI 从查询文本里自动猜帖子引用**：体验更顺。否决理由见上**猜错会静默拿到别人的帖子**。显式 `--thread` 是隐私边界上唯一可接受的默认。
- **直接输出 `relevantFloors` 作为引用链**（我第一版的做法）：实现最省事，且它确实"有输出"。否决理由：**实测它引用了错的人**。它在"哪些楼层与该话题字面相关"这个问题上是对的，在"这段对话里'楼主'指谁"这个问题上是错的  **两个问题不同，不能用同一个输出回答**。
- **在 CLI 里重新实现指代解析**：能完全控制输出格式。否决理由：**`resolve.ts` 已经做对了**（role/participantName/reason/confidence 齐全）。重写只会得到一个更差的版本，且会让两处口径漂移。
- **测试只断言"有输出"**：随便写都过。否决理由：**"有输出"正是第一版的错误状态**  它输出了两条引用，只是引用了错的人。新测试断言的是**引用链必须包含楼主的 `t1`/`t3` 且不含路人的 `t2`**。

## Consequences

- **CLI 现在有四个子命令**：`search` / `sources` / `query` / `thread`。
- **`resolve.ts` 与 `relevantFloors` 都被接线了**（此前零调用方）。
- **只支持已接入的平台**（bilibili / telegram-public），未接入的报明确错误而非静默失败。
- **未做**：多轮上下文（`resolve` 有 `cursorTurnId` 参数但 CLI 没暴露）、
  `sink` 沉淀对话证据（当前 `thread` 不写账本  对话证据的沉淀涉及隐私边界，
  需要单独决策，不顺手加）。

## 一次操作失误（记录）

修第一版显示层时我用 Python 做锚点替换，锚点字符串写的是我自己 Python 脚本里的
文本而不是文件内容，导致 `substring not found`；
而**更早一次失败的 shell 调用中，反引号被 shell 当命令替换执行了**，
`bash: normalizeThread: 未找到命令`，随后的 `python3 -c` 已经改坏了文件。

**教训**：用 shell 传含反引号的 Python 代码必须走文件（我这里就是），
且替换前先 `grep` 确认锚点在文件里真实存在。
