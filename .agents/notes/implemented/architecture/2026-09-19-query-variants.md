# Agent Note: 换语种重查  中文查询追加一次英文变体

Status: implemented

Decision-ID: query-variants


## Code

- `components/HX-Sagasu/src/recall.ts`

## Problem

**中文查询在这套来源上召回明显偏少。** 第 0 层 11 个来源，同一个问题换英文问：

```
  Rust 所有权        → 15 条  |  Rust ownership borrow checker  → 21 条   (+40%)
  阿司匹林 相互作用    → 13 条  |  aspirin drug interaction        → 21 条   (+62%)
  向量数据库 选型      → 13 条  |  vector database comparison      → 23 条   (+77%)
```

**三个查询全部上升，幅度 40-77%。**

而 aether-search 的 `RESEARCH_SYSTEM` 提示词里写着同一件事（`English first for volume`）
**两边独立指向同一个结论**，一边是它的经验，一边是我的实测。

我们此前**从不换语种**：`language-fit` 信号能**检出**「结果文字系统与查询不符」，
**但检出后没有任何动作**  那条信号只是个报告，不是触发器。

## Decision

**中文查询追加一次英文变体；改写不出就不补。**

### 为什么是词典级，不是 LLM 翻译

**翻译需要 LLM，而本组件零依赖**（无 `package.json`）。所以提供**可注入的改写器**，
默认实现是词典级：有内置词表 → 逐词替换；没有 → 返回 `null`。

**词典级必然不完备，但它的失败模式是安全的**：改写不出就退化成当前行为，
而**不是产出一个错误的英文查询去污染召回**。

### 三条判据

1. **至少替换掉一半的 CJK 词块才算成功**  只换一个词、其余全中文的查询，
   对英文后端没帮助，却可能因为多了一个英文词而**干扰中文后端**。
2. **拉丁词原样保留**  `Rust`/`Python` 本来就是英文。
3. **未命中的汉字必须累积成连续串，不能逐字分开**  见下（这是我第一版的 bug）。

### 与既有「不传 variants」注释的关系（读者会立刻问）

`recall.ts` 里有一段既有注释否决了「传 variants 全部」，理由是**结果集变大且混着错字文档**。
**那条否决仍然成立，与本决策不矛盾**：

| | 既有否决的 | 本决策的 |
|---|---|---|
| 变体性质 | **同语言**的多种写法（错字/正字） | **不同语言**的同义查询 |
| 并列的后果 | 返回并集，**混着错字文档**要靠判据筛 | 返回**不重叠**的新文档 |
| 实测 | 「微薄 热搜」拿回含错字的旧文 | 条数 13 → 21，**多出来的是新文档** |

### 变体失败不让来源失败

变体是**补充不是主路径**。它抛错时主查询的结果必须保住，且**不记成来源失败**
（否则「失败要响亮」的契约会被变体的网络抖动污染）。有测试锁住。

## Alternatives considered

- **接 LLM 做真正的翻译**：质量最高。**否决理由**：**本组件零依赖且要能离线跑**。而且·
  词典级的失败模式（改写不出就不补）**比 LLM 的更安全**  LLM 会**自信地译错**。
  留了 `QueryRewriter` 端口，将来要接 LLM 只需换注入。
- **对每个变体都扇出（不只英文一条）**：召回更全。**否决理由**：**请求数翻倍的成本是线性的，
  而收益不是**。实测只加英文一条就拿到 40-77%，加第二、第三条的边际收益未测 
  **先用一条量清楚再说**。
- **默认关闭，需要时开**：更保守。**否决理由**：实测收益明确（+23% 到 +85%），
  且失败模式安全（改写不出就退化成当前行为）。**默认开、留开关**比默认关更符合实测。
- **不在 recall 里做，改在 CLI 层拼查询**：层次更干净。**否决理由**：那会让**每个调用方
  各写一遍**（CLI、serve、将来的 MCP 入口），而**变体是召回质量的一部分**，不是展示的一部分。
- **让 `language-fit` 失败时触发重查**：复用既有信号。**否决理由**：`language-fit` 评的是
  **结果**，而那时请求已经打完了  **用它触发重查意味着第二轮请求**，成本翻倍；
  而本方案是**第一轮就带上英文**，请求数只从 1 变 2（而不是 1→1→2）。
  两条路可以并存，但当前实现选更省的那条。

## Consequences

- **第 0 层召回实测提升 23-85%**（四个查询的 A/B，见下）。
- **每个来源多打一次请求**  这是明确的成本，所以留了 `variants: false` 消融开关。
- **词表刻意小**（约 55 条，只收跨领域高频**名词性术语**） 完备性不是目标，
  **补不上就退化成原查询，代价是零**。
- **`QueryRewriter` 是端口**  将来接 LLM 翻译只需换注入，不动调用方。
