# Agent Note: 层级只决定"够不够"，不决定"什么排在前"  层内按话题契合度重排

Status: implemented

Decision-ID: in-tier-topic-reranking


## Code

- `components/HX-Sagasu/src/recall.ts`

## Problem

上一轮我给语言判据加了"诚实的边界说明"，并写下下一步计划是攻「权威的空壳」的剩下一族。这一轮把它做了，**结果是推翻了我上一轮的诊断**。

上一轮的诊断是：查询「Rust 所有权」时第 0 层是"权威的空壳"18 条全是无关的中文法律/资源论文。为此我加了话题契合度判据（`topic-fit`：擅长该话题的来源必须真的答上）与信息量判据（`evidence-substance`）。

线上实测发现：**这条判据全部通过，而且它是对的**。第 0 层**确实**拿到了相关结果`github` 返回了 `rust-lang/rust` 与借用检查器教程、`npm`/MDN 也各有产出，擅长 code 的来源共返回 12 条。所以第 0 层不是空壳。

真正的问题是**顺序**：来源按登记顺序拼接，而 `crossref` 登记在最前，它那 3 篇中文法律论文因此永远占据前三位。用户扫一眼前几条，看到的就是「一屏权威来源，没一条答问题」。

原来的诊断（"整层是空壳"）会导致错误的修法**丢弃整层**或**强制下降**，而两者都会把真正相关的 `rust-lang/rust` 一起扔掉。

## Decision

**把"层级"与"排序"两件事分开：层级决定要不要继续下降，排序在层内按话题契合度做。**

层内采用**三档稳定排序**，不引入任何跨来源分值：

1. **精确匹配**意图的来源（`ietf`↔`standards`、`mdn`↔`web-platform`、`pubmed`↔`biomedical`、`github`/`npm`↔`code`）
2. **契合**的来源（社区/代码类对任何工程问题）
3. 其余（学科语料库对非本学科问题）

组内保持来源给出的原顺序  这只是**重排**，不是打分。

配套：`topic-fit` 判据保留（它防的是"擅长来源真的零产出"那一族），`evidence-substance` 判据保留（防"命中与查询只有字面重合"）。

## Alternatives considered

**什么都不做 / 复用现有。** 最强理由是无需新增实现和维护成本. 现有状态仍存在 Problem 中的具体缺口, 因此采用本记录的选择

- **维持原诊断：第 0 层是空壳，应当丢弃或强制下降**：这是我上一轮写下的计划，看起来是"继续把上个决定做实"。**实测否决**：第 0 层里有 `rust-lang/rust` 这样的直接答案。丢整层会连它一起扔；强制下降则会让每一次查询都付出抓取第 1、2 层的代价，且第 1 层可能还没有第 0 层的那条结果。**诊断错了，修法就会错**这一轮最大的价值就是发现了这一点。
- **把不适配的来源从结果里过滤掉**：能直接消灭"看到的全是无关结果"。否决理由：会丢掉有用线索，而且会让 `evidence-substance` 之类的判据失去输入。重排达到同样的可见性效果，代价为零。
- **给来源算一个"相关度分"再排序**：更"科学"。否决理由：跨来源分值不可比这是本项目从第一轮就立下的规矩（B站的播放量、Crossref 的无分值、GitHub 的 star 之间没有换算关系）。三档稳定排序只用**可判定的归属关系**，不制造新数字。
- **用 embedding 算语义相关度**：唯一能真正判断"同语种但无关"的办法。否决理由：引入模型依赖与一个不可解释的分数，后者会重新带回"分高优先"。它在后续工作里，不在本轮。
- **把 `topic-fit` 的阈值调严（从"≥1"提到"≥3"）**：会让判据更常失败、更多下降。否决理由：实测显示擅长来源返回 12 条，调阈值只会让它永远通过，属于无意义的调节；判据本身没有错，错的是我没去看它的 detail。

## Consequences

- `recall` 的返回值顺序不再是"纯登记顺序"，而是"话题契合度分档 + 组内登记顺序"。这是一个**新的可观测行为**，调用方若假设了纯顺序会受影响当前没有这样的调用方。
- 意图分类是基于形态学信号的正则，会误判（如"什么是 HTTP 缓存"落进 `general`）。因为误判的代价是"少一次重排"而不是"过滤掉结果"，所以可接受；但这也意味着重排的效果依赖意图判得准。
- `SOURCE_SCOPE` 表是手工维护的，新增来源必须补一行，否则它默认"契合任何意图"（保守选择：宁可少重排，不要错排）。
- 话题判据 `topic-fit` 在实测的所有查询上都通过**它目前没有在线上触发过**。它防的是"擅长来源零产出"这一族，属于**未被观测到但合理存在**的失效，因此保留；但不应把它计入"已验证有效的修复"。
