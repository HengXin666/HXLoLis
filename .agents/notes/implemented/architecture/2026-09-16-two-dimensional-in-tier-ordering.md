# Agent Note: 层内排序是二维的  字面相关性优先于来源话题契合

Status: implemented

Decision-ID: two-dimensional-in-tier-ordering


## Code

- `components/HX-Sagasu/src/recall.ts`

## Problem

上一轮加完覆盖度判据后，我打算做"候选来源去重"。**实测先推翻了这个问题本身**：

- 三个查询里**跨来源同标题重复是 0**，精确 URL 重复也是 0
- 唯一发现的重复是 **Crossref 自己返回两条完全相同标题的记录**（「服务端渲染」→《汽车后市场服务模式创新研究》两条）

但实测顺带量出一个真问题：**无关结果按来源登记顺序占据固定名额**。覆盖 0 个查询词的命中占到 `6/22`、`9/20`、`6/21`约**三分之一的结果与查询毫无字面关系**，而它们占着固定配额，把相关结果往后挤。

同时暴露一个**口径不一致**：`Intl.Segmenter` 的 zh-Hans 词典缺技术词，实测把「服务端组件原理」切成 `服务|端|组|件|原理`**核心概念「组件」被切碎**，于是「React 服务端组件原理」的 17 条全部只能匹配 1/3 个词，被覆盖度判据一律判否。而 `termStreams` **本来就产出 bigram 流**（注释写着"保证 2 字查询与未登录词可召回"），覆盖度却只用了词流：**检索侧用 bigram 召回，判定侧不用**，于是"能召回到"的东西被判为"不相关"。

## Decision

**层内排序改成两维，且顺序是"字面相关性 → 来源话题契合"。**

- **第一维**：`isQueryRelevant`  是否覆盖 ≥ 1 个查询词（排除完全无关）
- **第二维**：来源是否精确匹配查询意图 → 是否契合 → 其余

**两处口径分工明确，且都写进注释**：

| 用途 | 函数 | 阈值 | 回答的问题 |
|---|---|---|---|
| 排序 | `isQueryRelevant` | ≥ 1 词 | 这条**沾边**吗 |
| 充分性 | `queryCoverageSignal` | ≥ 2 词且 ≥ 50% | 这一层**在回答这个问题**吗 |

另外：`queryTerms` 纳入 CJK bigram（与检索侧一致）；新增 `dedupeWithinSource` 只合并**同来源**的重复标题。

## Alternatives considered

- **什么都不做，只做同源去重**：这是本轮原本的计划，改动最小。否决理由：同源重复实测只出现 1 次，修它几乎不改善结果；而"三分之一的结果与查询毫无字面关系并占据固定配额"是用户**每次检索**都会遇到的事。修小问题不修大问题是错的优先级。
- **跨来源也按标题去重**：能让结果列表更短更"干净"。**明确否决**：两个独立来源给出同一结论是**相互印证**而不是冗余；合并会让 `source-diversity` 判据失真，而那条判据防的正是"一个来源的 N 条本质是一条"。而且实测跨来源重复为 0，没有需要解决的问题。判定"两条不同来源的结果是否同一件事"需要语义理解，不是标题相等。
- **排序只用"字面相关性 ≥ 2 词"**（我先这么写了，被实测推翻两次）：`Rust 所有权` 里 GitHub 的 `rust-lang/rust` 只匹配 1 个词，会落进"不相关组"；而 Crossref 那篇含"所有权"的中文法律论文匹配 2 个词，落进"相关组" → **法律论文排第一**。这是真的冲突：论文**字面上**确实比那条仓库更贴合查询。字面覆盖率做不到区分"含这些字"与"在讲这件事"。
- **排序只用来源维度**（我第一版写成了这样）：实测第 4 位是 npm 的 `@formatjs/icu-messageformat-parser`（覆盖 0 个查询词），它排在一堆**可能相关**的 MDN/Wikipedia 条目之前只因为 npm 与查询意图同为 `code`。一条 0 覆盖的包名对用户毫无价值，它凭的只是"来源对口"这个**先验**。直接证据（内容覆盖）必须强于先验（来源学科归属）。
- **给 `isQueryRelevant` 和 `queryCoverageSignal` 用同一个函数**：更"一致"。否决理由：两者回答的是**不同问题**"沾边吗"与"够回答我的问题吗"。上一轮测试 `层内按话题契合度稳定重排` 与 `覆盖度判据复现真实失效` 同时失败，正是这个冲突的显影；强行统一会让其中一个失效。口径不同但**理由写在同一个注释块里**，这不叫不一致，叫职责分离。
- **把 `Intl.Segmenter` 换成带技术词典的分词器**：能从根上解决「组件」被切碎。否决理由：引入一个依赖（本项目零依赖），且需要维护词表而 `termStreams` 的 bigram 流**已经在做这件事**，只是覆盖度没用它。复用它零成本。
- **对 latin 词也取 bigram**：否决理由：会把 `webpack` 切成 `we/ep/pa...`，让任何含 "pa" 的标题都算"沾边"，判据立刻失去意义。

## Consequences

- **前 6 条命中里的无关结果从 2-6 条降到 0 条**（四个查询实测）。
- `isQueryRelevant` 只排除"0 覆盖"，**不排除"1 覆盖但话题不对"**。所以「服务端渲染」这类查询的首位仍可能是 Crossref 的《汽车后市场服务模式创新研究》它字面覆盖了"服务"。**这是已知局限**：判据证明"这些字出现了"，不证明"这条在讲这件事"。根除需要语义理解。
- `queryCoverageSignal` 的分母现在含 CJK bigram（词数变多），所以覆盖比例的数字与之前不可直接比较。测试已改为不写死数字，只断言最佳覆盖数。
- `normalizeTitle` 只用于判同，不用于展示展示文本永远是来源给的原样标题（**不许改写证据**）。
- 引入了一条新的代码卫生要求：任何**消费 query 的匹配函数**都必须给 `undefined` 加保护（本轮 `queryCoverageSignal`、`substanceOfHit`、`queryTerms` 都做了），否则 `RecallContext` 缺 `query` 时会抛 `TypeError` 而不是"放行"。

## Verification

- `bash components/HX-Sagasu/scripts/test.sh` → **132 tests / 132 pass / 0 fail**
- 新测试：`匹配口径必须包含 bigram`（断言「组件」是匹配项、单字不是）、`bigram 只取含 CJK 的`（`webpack` 不得被切碎）、`排序口径: 排除完全无关`、`充分性口径比排序口径更严`、`同来源同标题只保留一条`、`跨来源同标题不合并`、`标题归一化只用于判同`
- 两个旧测试在本轮**先失败后修正**（`层内按话题契合度稳定重排`、`覆盖度判据复现真实失效`）它们的失败是"阈值定 ≥2 会让法律论文排第一"这个真冲突的显影，不是测试写错
- **线上实测**（修复前后对比）：
  - 前 6 条里的无关结果：`Rust 所有权` 2→0、`CSS 作用域` 0→0、`React 服务端组件原理` 6→0
  - `Rust 所有权` 前三全部是 GitHub 的 Rust 借用/所有权教程（2/2 覆盖）
  - `CSS 作用域` 前三全部是 MDN 的《作用域》《全局作用域》《局部作用域》
  - 同源同标题重复：1→0
- **诚实记录未解决的部分**：「服务端渲染」首位仍是 Crossref《汽车后市场服务模式创新研究》（字面覆盖"服务"）。字面判据到此为止。

## 修复过程中的两个操作教训

- `edit` 工具在这轮有多次 `old_string` 失配（注释块被前一次编辑改动过）。**教训: 改注释块的锚点必须用最近一次读到的原文，不要凭记忆**；连续失配时应改用按行号的脚本编辑。
- 一次脚本插入把 helper 函数**重复插入了两遍**，导致三个测试文件 SyntaxError。**教训: 脚本编辑后必须立刻 `grep` 确认定义只出现一次，再跑测试。**
