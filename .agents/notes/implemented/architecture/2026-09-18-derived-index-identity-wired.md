## Problem

目标第 (4) 项要求把检索结果沉淀为**可复用、可全量重建、带版本身份**的数据资产。
实现 `index-store.ts` 早就写好了，注释甚至写着：

> `loadOrRebuild` 存在的**全部意义**就是这件事  "判断被收进这里，就不可能被忘记"。

**而它此前零调用方。** CLI 的 `cmdQuery` 直接 `JSON.parse` 索引文件喂给 `queryIndex`，
**完全绕过了身份校验**。

后果具体而危险：

| 变更 | 索引侧 | 查询侧 | 用户看到 |
|---|---|---|---|
| 分词器升级（`TOKENIZER_VERSION` +1） | 旧口径的倒排键 | 新口径的词 | **查不到，不报错** |
| 打分公式改版（`INDEX_FORMAT_VERSION` +1） | 旧公式的 score | — | 同上 |
| 卡片增删（`sourceDigest` 变） | 缺/多卡 | — | 同上 |

**三种情况下调用方看到的都是"没有结果"，而真相是"索引过期了"。**
这正是本项目一路在防的形态：**把「机制失效」伪装成「没有内容」**。

## Decision

**`cmdQuery` 走 `loadOrRebuild`，并在三种情形下给出不同的话。**

1. **身份通过** → 明说"校验通过（未重建）"。
2. **身份不符** → 逐字段报出差异（`tokenizerId: 索引 v0 → 账本 v1`）+ 全量重建 + **回写**。
   回写失败要单独报（`重建后回写失败（本次查询仍有效）`） 副作用失败不能假装没发生。
3. **未提供账本** → **如实说"无法校验身份"**，并说明索引是派生品、只读索引无法判断是否过期。
   仍然给出结果，但标明 `⚠ 未校验身份`。

**为什么第 3 种不直接拒绝执行**：索引仍是有用的（它至少指向卡 id）；
拒绝执行会让人以为"索引是坏的"，而实际是"无法判断它是否新鲜"。**如实标注胜过拒绝。**

## Alternatives considered

**什么都不做 / 复用现有。** 最强理由是无需新增实现和维护成本. 现有状态仍存在 Problem 中的具体缺口, 因此采用本记录的选择

- **让 `loadOrRebuild` 在 `queryIndex` 内部自动调用**：调用方彻底不会忘。否决理由：**`queryIndex` 是纯函数**（吃 `DerivedIndex` 吐结果），把"读文件 + 重建 + 回写"塞进去会让它变成有副作用的操作。而且重建需要账本，而 `queryIndex` 拿不到账本  强行合并会逼出一个"可选账本参数"，比现在更难理解。
- **索引身份不符时直接报错退出**：最简单。否决理由：**派生索引是可丢的，真相在账本里**  身份不符不是错误状态，是**正常的生命周期事件**（换个分词器就该重建）。报错会让用户以为要手工修，而正确行为是自动重建、继续查询。
- **不提供"无账本"的降级路径**（强制要求 `--ledger`）：能保证每次查询都可信。否决理由：**有些场景确实只有索引**（比如从别处拷来的索引快照）。强制要求会让这条路彻底断掉，而降级 + 明确标注既保住了可用性又没丢掉诚实。
- **给 CLI 加 `--rebuild` 子命令手工重建**：让副作用显式。否决理由：**那等于把"忘记重建"变成默认**。身份校验的价值恰恰在于**自动发生**  加一个手工命令，就会有人忘记运行它。
- **修完 CLI 后不写测试，因为端到端已经手验过**：省事。否决理由：**本项目已经两次栽在"手验过但测试没覆盖"上**。三条新测试分别锁住分词器升级、源摘要变化、索引损坏三种情形  而手验只覆盖了第一种。

## 一个只有真跑一次才看得见的缺陷

`cmdSearch` 的 `--sink` 分支写着：

```js
writeFileSync(sinkPath, ledger.toJSONL() + (ledger.size > 0 ? chr(10) : ''), 'utf8')
```

**`chr(10)` 是 Python 语法。** 在 JS 里它会抛 `ReferenceError: chr is not defined`。
也就是说 `search --sink` **在运行期是坏的**，而 **220 项测试全绿** 
因为测试跑的是 `src/` 的模块，**不跑 CLI**。

修法是 `'\n'`。端到端实测：18 条命中 → `账本 /tmp/t.jsonl: 18/18 新增` → 索引 18 张卡。

**这条与本轮修的 `loadOrRebuild` 没接线是同一个病**：机制写好了、测试绿了，
**而它从来没被真的跑过一次**。argv 里的那行 Python 语法就是这个病的物证。

### 我自己的操作失误（记录以备复现）

修 `cmdQuery` 时我用 Python 做字符串替换，`rindex('/**', 0, i)` **定位到了错误的注释起点**，
把 `flagOf`/`usage`/`buildFetchers`/`cmdSearch`/`cmdSources` 整段删掉了。
文件是未跟踪状态（`??`），**git 恢复不了**，只能按本轮读过的内容重建。

重建是忠实的（本轮读过全部 213 行），且**顺手修掉了 `chr(10)`**。
教训：**用锚点替换大段代码时，锚点必须验证唯一性**  而不是取"最后一个 `/**`"。

## Consequences

- **CLI 的 `query` 现在需要 `--ledger` 才能校验身份**。不给则降级为"未校验"，并明确标注。
- **重建会回写索引文件**（副作用）。这是刻意的：不回写等于每次查询都重建。
- **`queryIndex` 与 `loadOrRebuild` 都被接线了**  两者此前都是零调用方。
- **仍未接线**：`resolve.ts`（L2 指代消解，本会话实测它的核心场景是好的但没入口）、
  界面（`serve.ts`）不写账本  那是刻意的，界面是观察工具，沉淀由 CLI 显式发起。
