# Agent Note: 多轮上下文接线  "楼上"终于有确定含义了

Status: implemented

- 影响: `components/HX-Sagasu/scripts/sagasu.ts`（`thread` 子命令加 `--at` 游标 + 歧义输出）
- 相关: `src/resolve.ts`（实现未变，`cursorTurnId` 此前**零外部调用方**）

## Problem

目标第 (3) 项列了四项：错别字容错、帖子-回复结构、引用链、**多轮上下文**。
前两项在两个会话前接通了（错别字容错见 `2026-09-18-normalize-must-reach-query-terms.md`），
引用链在第 23 轮接通了。

**多轮上下文没通**：`resolve(thread, question, cursorTurnId)` 的第三个参数
**零外部调用方**（除测试外），而它的注释写着：

> `cursorTurnId` 是"当前正在读哪一楼"，只有它存在时"楼上"才有确定含义。

于是 **"楼上"永远解析不出来**  `resolve` 只能报歧义。能力在、契约在、测试在，**没有入口**。

这已是同一形态在本项目的**第六次**出现（前五次：`resolve` 核心场景、`loadOrRebuild`、
`resolve`、`url-safety`/`readability`、`normalize` 的归一结果）。

## Decision

**CLI 的 `thread` 子命令加 `--at <楼层号>`。**

```
sagasu thread bilibili:BV1GJ411x7h7 --ask "楼上说得对吗" --at 6
```

**用楼层序号而不是 turnId**：人读帖子时数的是"第几楼"，不是 hash。
序号在内部转成 `turnId` 再传给 `resolve`。

**越界要响亮**：`--at` 超出 `1..N` 直接报错并给出合法范围，不静默截断 
静默截断会让人以为"游标生效了"，而实际定位到了别的楼层。

## Alternatives considered

- **不暴露游标，让 `resolve` 自己猜一个最近楼层**：体验更顺（不用记楼层号）。否决理由：**"楼上"在没有阅读位置时语义上就是不确定的**。`resolve` 的实现刻意在无游标时返回 `ambiguous` 而不是猜一个  注释写着"给出候选让人来定，不替人定"。**猜一个等于编造引用来源**，而引用链的全部价值在于它能指回**具体**楼层。
- **用 `turnId` 而不是楼层序号**：与内部表示一致，实现更直接。否决理由：**人不会去数 hash**。用序号是"按使用者的心智模型设计接口"而 `resolve` 内部仍然用 id（它需要稳定标识），转换只发生在 CLI 边界这一处。
- **`--at` 越界时截断到最近合法楼层**：更宽容。否决理由：**那会让"游标在第 6 楼"这句话变成假话**（实际定位到第 11 楼）。这类静默纠正正是本项目一路在防的形态。报错 + 给合法范围，人能立刻改对。
- **把歧义信息吞掉，只说"没解析出目标"**：输出更干净。否决理由：**用户会不知道该怎么办**。歧义信息里带着"为什么"（无游标）与"怎么办"（用 `--at`），那是可操作的信息。**报出问题必须同时报出解法**，否则只是把困惑转嫁给用户。
- **在界面（`serve.ts`）也加 thread 端点**：让对话语义可视化。**本轮没做**  它需要一组新的交互（帖子上方显示楼层列表、点某楼设为游标、再问问题），是一个独立的界面设计，不该和 CLI 接线挤在一次改动里。列为下一步。
- **不写测试，因为端到端已经手验过**：省事。否决理由：**本项目已经反复栽在"手验过但测试没覆盖"上**。三条新测试分别锁住：有游标能解析、无游标必报歧义、**首楼无「楼上」时不报错也不编造**（最后这条是边界情形，手验时没想到）。

## Consequences

- **`cursorTurnId` 现在有真实生产者**  "楼上"可用。
- **第 (3) 项的四项需求现在全部有真实入口**：错别字容错（`queryTerms` 前置归一）、
  帖子-回复结构（`normalizeThread`）、引用链（`resolve` 的 `targets[].turns`）、
  多轮上下文（`--at` 游标）。**四项都借道 `sagasu thread` 这一个命令。**
- **仍未接线**：`parentId`/`quotedTurnId` 除了 `resolve` 的第三人称路径外没有消费者 
  帖子-回复的**树形结构**（谁回复谁）没有被任何输出呈现。CLI 现在只按楼层顺序平铺。
- **界面无 thread 端点**（见上）。
