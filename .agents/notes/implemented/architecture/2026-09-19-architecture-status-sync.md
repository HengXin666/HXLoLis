## Problem

收尾验收时核对目标要求的三个产出，发现**架构方案的 §十一「当前实现状态」停在 09-18**：

| 项 | 文档写的 | 实际 |
|---|---|---|
| 来源登记 | 26 / 44 条 | **45 条** |
| 适配器覆盖 | 2/9 ready | **2/12 ready** |
| 取数器 | 未写 | **45 个**（argo 不可用时退化 14） |
| 测试 | 未写 | **311 通过** |
| 模块表 | 缺 5 个新模块 | `query-variants` / `verify-links` / `fallback` / `reply-tree` / `scope-resolve` |

**一处「文档说已完成、而实际更少」是本项目反复栽过的形态**（6 次），
而这里是它的镜像：**文档说得比实际少**  同样有害，因为读者会以为能力还没建。

## Decision

### 一、§十一 就地重写（不追加变更史）

模块表从 8 行扩到 **11 行**，补上五轮里新增的能力，每行都带**复算命令**：

```
| L1 查询变体 | query-variants.ts | 已接线  每来源多打一次英文变体（A/B 实测 +57%） | variants: false 消融 |
| L3 核验   | verify-links.ts + fallback.ts | 已接线  search --verify | CLI 实测 |
| 执行时间线 | sagasu search --explain | 已接线  区分「慢」与「排队」 | CLI 实测 |
```

并补上测试规模/源码行数/note 篇数三个总数。

### 二、散落的过时数字就地修正

`2/9 ready`（两处）→ `2/12`；`我们 26 条登记` → `45 条`。

### 三、顺带清掉一处历史写入失误

那个文件里有 **48 处 `\`` （转义的反引号）**  是我更早用脚本写入时留下的。
一起清掉：markdown 里它应该就是裸反引号。

## Alternatives considered

- **不改，反正 note 里都有**：省事。**否决理由**：**架构方案是目标明确要求的交付物之一**，
  而它现在会让人以为「只有 26 条来源、2/9 平台」。**读者不会去翻 57 篇 note 才能知道现状。**
- **另写一份「2026-09-19 状态更新」**：保留原状。**否决理由**：**本仓库规则明写「事实就地重写」**，
  而且两份文档会各说一半、读者无法判断该信哪份。
- **只改 §十一，不改散落的数字**：改动更小。**否决理由**：**`2/9` 与 `26 条` 在正文里**
  （§六 覆盖率、§十二 诚实边界），读者会先看到它们  **只改一处等于没改**。
- **把 48 处转义反引号留着**：与本次目的无关。**否决理由**：**它在渲染时会显示成 `\``**，
  也就是读者看到的多一个反斜杠  那正是「文档在骗人」的另一种形态。**顺手清掉成本极低。**
- **把 `evolution-log` 的历史数字也改掉**：更「一致」。**否决理由**：**那份档案明确声明
  「不做删减与美化」，它的价值就是记录当时的事实**。改它等于销毁证据。

## Consequences

- **架构方案的实现状态与实际一致**  11 个模块层、45 条来源、2/12 平台、311 测试。
- **48 处转义反引号被清理**，markdown 渲染正常。
- **`evolution-log` 的历史数字刻意不动**  它是档案，不是现状描述。
