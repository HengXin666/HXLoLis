# Agent Note: 权威层必须同时满足「有供给」与「在回答这个问题」

Status: implemented

- 影响: `components/HX-Sagasu/src/{recall,authoritative,authoritative-tech}.ts`

## Problem

上一轮落地了"权威优先"的分层召回：第 0 层够用就停止下降。这一轮补上技术与中文权威来源（MDN/IETF/npm/Stack Overflow/掘金）之后，线上实测暴露出充分性规则的一个**结构性缺陷**。

查询「Rust 所有权」：第 0 层返回 18 条、标识符覆盖 18/18、7 个来源全部成功按当时的规则，**完美满足条件，系统停在第 0 层**。但翻看结果：前几条是 Crossref 上的《全民所有自然资源资产所有权委托代理模式探究》《权利冲突视角下所有权保留的性质探析》。它们确实含"所有权"三字，所以任何基于字符匹配的判据都会认为它们相关；而它们与 Rust 毫无关系。

危害不是"相关性弱"，而是**它满足了充分性条件**：条数够 → 停止下降 → 真正可能有答案的中文技术社区（第 1 层）被挡在外面。用户看到一屏权威来源，没有一条回答了问题。

同时暴露出另外两个实现级缺陷：

- **工厂函数没被调用**：`EXTENDED_SOURCES` 里放的是 `mdnSearch` 这个**工厂**而不是 `mdnSearch()` 的**结果**，于是 recall 用 `(query, limit)` 调用它，拿到一个函数，`got.slice` 抛 `TypeError`。5 个来源因此静默变成"0 条命中"。
- **登记表重复**：本轮编辑把 4 个新来源写了两遍，同一次召回里它们被取两次，命中数从 15 虚增到 18。既有测试一条都没抓到。

## Decision

**充分性判定从"条数够"改成"四条可复查判据全过"，并修掉两个实现缺陷。**

规则 `AUTHORITATIVE_FIRST` 现在产出 4 个 `TierSignal`（各带 `name/ok/detail`），全过才算够用：

| 判据 | 含义 | 防的是什么 |
|---|---|---|
| `authoritative-supply` | 第 0 层**成功**返回 | 把失败当空 → 安静降级 |
| `volume` | 命中数 ≥ `minHits` |  |
| `language-fit` | 结果文字系统与查询吻合 | "权威的空壳"挡掉对应语料的社区层 |
| `source-diversity` | 结果来自 ≥ 2 个独立来源 | 单一来源的 N 条本质是一条 |

配套改动：

1. `RecallContext` 增加 `query`（语种判据需要知道查询是什么）与 `minSources`；`RecallResult` 增加 `verdict`（**含未通过项**），使"为什么没停"可复查。
2. 取数函数返回非数组 → **响亮报错**（`实现有误，不是"没有内容"`），不再被吞成 unknown。
3. 层内来源改为**并行**取数（权威接口是本层最慢的部分，串行会让一次召回退化到十几秒）。
4. 新增 `scripts/test.sh` 级别的守卫测试：登记表不允许重复 id、`SOURCES` 与实现表双向一一对应、每个来源一次召回最多被取一次。

## Alternatives considered

- **只用字符系统判据就够了**：实现只要十几行，且确实抓到了"中文查询 → 一屏英文结果"这一族失效。**实测否决**：线上确认它**抓不到**真正的那个案例Crossref 返回的是中文论文，文字系统是匹配的。判据通过、系统仍停在 L0。保留它（它消掉了一族），但注释与测试都写明**能力边界**，避免后人以为问题已解决。
- **做语义相关性判断（embedding 相似度）来决定够不够**：这是真正能解决问题的方向。否决理由：本组件目前不引入任何模型依赖（零依赖设计），且一个不可解释的相似度分数会重新引入"分高优先"那正是上一轮明确否决的。它是后续工作，不是本轮该偷偷塞进来的东西。
- **给每个来源标注"擅长的话题"（Crossref 擅长学术、MDN 擅长 Web 平台）**：更贴近根因，实现也只是查表。否决理由：这会变成一张手工维护的话题分类表，而它的准确性同样无法验证与上一轮否决的"权威网站白名单"是同一类问题（无法执行、无法反驳、会腐烂）。**能落地的版本**是让来源自己声明话题标签，但当前这些开放接口都不提供，只能靠人工，代价与收益不匹配。
- **把语种判据失败直接当成"这一层作废"，整层丢弃**：更激进，能确保下降。否决理由：第 0 层的命中并非**全部**无用（`github` 返回的 rust-lang/rust 就是相关的），整层丢弃会把有用结果一起扔掉，而"部分有用"恰恰是常见形态。判据只影响"是否够用"，不影响"是否采纳"。
- **让 `recall` 在取数函数返回非数组时静默跳过**：更宽容，不会让一个写错的来源拖垮整次召回。否决理由：这正是本项目反复踩的"把实现错误伪装成没有内容"。响亮报错让错误在**第一次运行**就暴露，而不是在"某个来源好像没数据"的困惑里躺几个月。
- **保留重复登记（反正取两次只是多几条）**：否决理由：它让命中数虚增、消耗额外配额、让"来源多样性"统计失真，且**不报错**安静地污染充分性判断。加一条 id 唯一性测试的成本几乎为零。

## Consequences

- 语种判据**必要但不充分**：能抓"文字系统不匹配"，抓不到"同系统但无关"。**"权威层的空壳"问题没有被解决，只被削掉了一族。**这一点写进了源码注释与测试，防止后来者过度声称。
- `RecallContext.query` 是新增的必填字段，调用方必须传查询原文；传空/缺省时不做语种判断（**"拿不到查询"不等于"判定为不相关"**）。
- 判定结果现在是 `TierSignal[]` 而不是一句人可读的话，`stoppedBecause` 由 signals 拼成，可直接印进报告。
- 并行取数改变了失败收集方式：来源之间不再有确定的调用顺序，但 `usable` 的登记顺序仍决定 `tier.sources` 与命中拼接顺序，因此结果稳定。
- 新增的 5 个来源同样受"夹具只验证解析、不验证端到端"这一已知缺口的约束（见上一轮的 note）。
- **OpenAlex 的 `mailto` 只降低而没有消除 429**：同一次会话里既见 200 也见 429。因此它不能算稳定供给，上线前需要退避策略或换用带 key 的额度。

## Verification

- `bash components/HX-Sagasu/scripts/test.sh` → **106 tests / 106 pass / 0 fail**；
- 三个新判据各有测试：`语种不吻合 → 必须下降`、`来源多样性`、`没有查询原文时不做语种判断`；
- **能力边界有测试**：`已知边界: 同文字系统但话题无关时抓不到`，用的是线上真实的结果构成（中文论文 + 英文代码条目混排）；
- 两个实现缺陷各有测试：`登记表里不允许重复 id`、`取数函数返回非数组 → 响亮报错`、`每个来源在一次召回里最多被取一次`、`SOURCES 与实现表双向一一对应`；
- **线上实测**（非夹具）：第 0 层来源 15 个，查询 `Rust 所有权` 命中 18 条（来源分布 crossref/pubmed/github/wikipedia/mdn/npm 各 3），`transformer` 命中 27 条（9 个来源）扩展来源确实生效了（修复前它们全部因工厂 bug 报错）；
- **同时确认了判据的局限**：上述两个中文/混合查询都**通过**了 `language-fit` 并停在 L0，即"权威层的空壳"仍然存在。
