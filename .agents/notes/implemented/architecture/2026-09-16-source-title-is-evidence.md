# Agent Note: 来源的 title 必须是真实标题  它是覆盖度判据的输入

Status: implemented

- 影响: `components/HX-Sagasu/src/authoritative.ts`

## Problem

上一轮落地了覆盖度判据（`query-coverage`）：至少有一条命中要覆盖 ≥ 2 个查询词、且 ≥ 50% 的查询词。它读的是 `title` 与 `snippet`。

这一轮我去量"结果集本身的质量"，发现 PubMed 的实现**直接把这个判据废掉了**：

```
pubmed | PubMed 24558651
pubmed | PubMed 25191335
pubmed | PubMed 39687182
```

标题就是 ID 本身。源码注释写着理由："为了保持一次调用只发一个请求的简单性"。两个后果：

1. **覆盖度判据对它永远是 0**标题里没有任何查询词
2. **用户看到的结果列表不可读**一串数字 ID 不是证据

而我实测发现这个理由本身站不住：`esummary` **支持一次传多个 id**（`id=24558651,25191335`），所以代价是"每次检索多 1 个请求"，不是"每个 id 一个请求"。用一个额外请求换回可用的标题，这个交换显然是值得的。

修好之后立刻暴露出一个**真实且重要**的领域问题：查询「Rust 所有权」时 PubMed 返回的是 `Rust fungi and global change.`、`Effector proteins of rust fungi.`在生物医学语料里，**Rust 是小麦锈病**。这不是 bug，是"同一个词在不同学科里指完全不同的东西"，而它恰好说明覆盖度判据在工作：这些结果覆盖不了"所有权"。

## Decision

**PubMed 检索改为两段式：`esearch` 拿 id → `esummary` 批量拿真实标题、期刊与 DOI。**

- 一次 `esummary` 请求拿全部 id（不是逐个）
- 拿不到摘要时**退回** `PubMed <id>` 作标题（真实、不编造），而不是丢掉这条结果
- `esearch` 返回 0 条时**不再发**第二次请求
- `identity` 仍是 `pmid:<id>`权威性来自标识符，标题只是可读性
- `publisher` 用期刊名（`New Phytol`），比笼统的 "PubMed" 信息量更大

## Alternatives considered

- **什么都不做，保持标题为 id**：省一次请求，实现最简单，而且"不编造标题"本身是个正确的原则。否决理由：这个原则被用来论证一个**错误的取舍**真正的原则是"不编造"，而 `esummary` 给的是真实标题，不违反它。代价上，"多一次请求"被误估成"每个 id 一个请求"，实际是一次批量。不改的后果是覆盖度判据对一整类来源失效，且结果列表不可读。
- **只改覆盖度判据，让它对 `PubMed <id>` 这种标题宽容**：能避免改 PubMed 实现。否决理由：方向错了问题在**数据质量**不在判据。让判据宽容只会同时放过其它真实的低质量标题，而且用户仍然看到一串 ID。
- **用 `efetch` 取摘要全文代替 `esummary`**：信息更全（含摘要正文）。否决理由：`efetch` 返回 XML、体积大得多（每篇几 KB 到几十 KB），而这一层的用途是**给候选结果**，不是给全文。等有了"深读某一条"的入口再上 `efetch`。
- **把 PubMed 从第 0 层移除**（既然 "Rust" 在小麦锈病语料里会误导）：看起来能消除噪声。否决理由：对**生物医学查询**它是不可替代的一手来源（实测「p53 基因突变与肿瘤」覆盖 4/4，首位 `Understanding p53 functions through p53 antibodies`）。跨学科的同词异义是**检索的固有属性**，正确做法是靠判据识别，而不是删掉一个学科语料库。
- **在 `pubmedSearch` 内部加学科预筛**（非生物医学查询直接返回空）：能少发两个请求。否决理由：那需要"什么算生物医学查询"的判断，而判断错会让一个正确来源被静默跳过；发请求后再由覆盖度判据否决，代价只有一次 HTTP，且**判断依据是真实结果而不是猜测**。

## Consequences

- PubMed 每次检索的请求数从 1 变成 2（有时间隔的批量，不是 N+1）。这在第 0 层是并行取数的，所以不显著拖慢整体。
- 结果列表从"一串 ID"变成可读的论文标题这是用户直接可见的改善。
- **顺带发现一个真实的领域陷阱并记录下来**：`Rust` 在 PubMed 里指小麦锈病（`Puccinia` 属真菌），`p53` 这类查询则完全正常。同词异义是跨学科检索的固有属性，不该靠删来源解决。
- 覆盖度判据现在对 PubMed 真正生效了：`Rust 所有权` 的最佳命中来自 GitHub，PubMed 的中文/生物医学命中不再"白占"覆盖度。
- **修复过程中发现并清除了一个自己造成的文件损坏**：`tests/authoritative.test.ts` 里残留了一个 NUL 字节（来自上一次编辑留下的占位字符串），使该文件被识别为二进制、`read` 工具拒绝读取。已用 Python 按字节清除并确认 `file` 判定恢复为 UTF-8 文本。教训：**不要为了"先占位"往测试文件里写控制字符**。
