# Agent Note: 私域平台可达性复核  以及一次「只看状态码」的误读

Status: implemented

Decision-ID: private-platform-reachability-recheck


## Code

- `components/HX-Sagasu/src/adapters/registry.ts`

## Problem

需求 (2) 是四条里**唯一未达标的**（2/12 ready）。收尾前做一次**逐平台实测复核**，
确认那些 `blocked` 状态是**外部约束**而不是我的疏漏。

### 第一轮探测（只看状态码） 得到了一个**误导性的结论**

```
小红书     HTTP 200  349ms        ← 看起来「通」
知乎       HTTP 200  289ms        ← 看起来「通」
微博       HTTP 200  600ms        ← 看起来「通」
微信公众号  HTTP 200  146ms        ← 看起来「通」
小黑盒     HTTP 200  221ms        ← 看起来「通」
百度贴吧   HTTP 403   73ms
X.com / Discord / Reddit / YouTube  ✖
```

**我当时写下了「6/10 平台可达」**  但那**只看主页与状态码**。

### 第二轮：探具体端点

| 平台 | 端点 | 实测 |
|---|---|---|
| 小红书 | `edith.xiaohongshu.com/api/sns/web/v1/search/notes` | **404** |
| 知乎 | `api/v4/search_v3` | **403 + `need_login: true`** |
| 微博 | `m.weibo.cn/api/container/getIndex` | **HTTP 200 / 9380B  但内容是 HTML 登录页** |
| 贴吧 | `mo/q/m?kw=` | **403** |
| 小黑盒 | `api.xiaoheihe.cn/bbs/app/api/general/search` | **404** |
| B站（对照） | `search/type` 不带 Referer | **412**；**带 Referer 后正常** |

**微博那条是决定性的**: 它返回 200 且体积不小（9380 字节），
**而内容 `<!DOCTYPE html>` 是一个登录页**。

**只看状态码会把它判成「通了」**  而它什么都没有。

## Decision

### 一、结论不变: `blocked` 状态是对的

**逐平台的解锁条件无需修改**  既有登记（09-16/09-18 实测）经住了 09-19 的复核。

### 二、把 09-19 的复核证据补进登记表

`evidence` 字段的意义就是**可复查的实测记录**，所以补上:

- `weibo`: 「该端点确实返回 HTTP 200 / 9380B，但**内容是 HTML 登录页而非 JSON**
   **只看状态码会误判为"通了"**」
- `tieba`: 「09-19 复核 5 个端点: 4 个 403 + `c/f?kw` 返回 200 但 0 字节空壳」

**这条补充的价值不在结论，在于把「为什么它不是通的」写清楚了** 
否则下一个看到 `HTTP 200` 的人（可能就是几轮后的我）会重走一遍。

## Alternatives considered

**什么都不做 / 复用现有。** 最强理由是无需新增实现和维护成本. 现有状态仍存在 Problem 中的具体缺口, 因此采用本记录的选择

- **保留「6/10 可达」这个结论**：它是实测的，且数字好看。**否决理由**：**它是误读** 
  主页可达不等于**内容可取**，而需求 (2) 要的是**内容**。
  **一个误导性的乐观结论比一个准确的悲观结论更坏**，因为它会让人停止排查。
- **把 `weibo` 从 `blocked-anti` 改成 `ready`**：既然 200。**否决理由**：**那正是误读的产物** 
  拿不到数据的通道不是 `ready`。这会在下游制造「为什么这个来源总是空」的困惑。
- **只写 Note 不改登记表**：改动更小。**否决理由**：**`evidence` 字段是给代码旁边的人看的**，
  Note 在 `.agents/notes/` 下。**这两条实测放在登记表里才有人读。**
- **把 10 个平台全部重探一遍并重写 evidence**：更彻底。**否决理由**：**既有 evidence 已经准确**
  （复核证实了这一点），重写是**没有新信息的工作**。只补**本轮新增的观测**。
- **标记需求 (2) 为「已尽力」而不写清原因**：省事。**否决理由**：**2/12 是一个会被追问的数字**，
  而「为什么」必须能被独立复核  现在它在 `evidence` 里。

## Consequences

- **需求 (2) 的 2/12 有完整的一手证据支撑**  每个未达标平台都写了端点、状态码与原因。
- **登记表补了两条 09-19 复核**  其中 weibo 那条明确警示「只看状态码会误判」。
- **一处我自己的误读被记录**: 我用「主页 HTTP 200」得出了「6/10 可达」，
  而**具体端点全部不可取数据**。
