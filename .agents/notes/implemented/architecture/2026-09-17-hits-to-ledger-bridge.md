# Agent Note: 检索结果到账本的桥  第 (4) 项需求的缺口

Status: implemented

- 影响: `components/HX-Sagasu/src/sink.ts`（新增）、`components/HX-Sagasu/tests/sink.test.ts`（新增）

## Problem

第 (4) 项需求是"把检索结果沉淀为可复用、可全量重建、带版本身份的数据资产"。两侧都建好了，**中间没有桥**（2026-09-17 实测确认）：

```
recall()          → SourceHit[]      检索结果，内存里，会话结束即丢
EvidenceLedger                       只追加账本，内容寻址
cardsFromThread()                    Thread → 卡（那是**读线程**那条路，不是检索）
ingest-truth.ts                      只处理**引擎真值**（哪个引擎坏了），不处理召回结果
```

全仓库搜 `SourceHit` 的消费点：只有 `authoritative.ts` 与 `authoritative-tech.ts`（生产它），**没有任何地方把它写进账本**。于是"搜到的东西"从来没有成为资产这正是第 (4) 项需求缺的那一段。

## Decision

**新增 `src/sink.ts`：把 `SourceHit[]` 追加进 `EvidenceLedger`。**

一条不能含糊的契约: `EvidenceCard.quote` 的定义是"原文字面引用，**必须能在源站核对得上**"。检索结果里满足条件的只有两个字段：

| 字段 | 为什么可以当 quote | 实测 |
|---|---|---|
| `snippet` | 来源给出的**原文片段** | GitHub 仓库描述、Wikipedia 正文、MDN 正文 |
| `title` | 来源给出的**原样标题** | 仓库全名、条目名、页面标题 |

**`url` 不许进 quote**  它是坐标不是内容。**任何我们生成的文本**（摘要、翻译、拼接、归一化）也不许。两者都空时**拒绝造卡**并计数上报。

## Alternatives considered

- **什么都不做，让检索结果继续只活在内存里**：改动最小，而且 `recall()` 的调用方（agent）自己会用结果。否决理由：**那正是第 (4) 项需求要消灭的形态**"搜完就散了"。run 级快照不等于资产；资产要能被下一次会话检索到。不做这一步，前 16 轮建的账本与索引全部没有输入源。
- **把 `url` 也当 quote**（title 为空时兜底）：能让"每条命中都能造出卡"，覆盖率 100%。否决理由：**链接本身不主张任何事**。下游引用时会引到一条 URL 而不是一句话，而 `quote` 字段的全部意义是"这段原话出处在哪"。宁可少一张卡（并报出少了几张），也不要一张无法核对的卡这与全项目的失败契约同源。
- **`title` 与 `snippet` 拆成两张卡**（各自独立成证据）：能让"标题命中了但摘要没命中"这类情况被更精细地检索到。否决理由：它们描述的是**同一个东西**（一条命中）。拆开会让同一份证据在账本里出现两次，而 `sourceDigest` 与去重都按卡计**重复会污染 `source-diversity` 这类判据**，而那个判据是充分性判断的七信号之一。
- **卡的身份里带上 query**（`{platform, threadId, turnId, quote, query}`）：能回答"这条是搜什么问题搜到的"，看起来信息更全。否决理由：**同一份内容换问法仍是同一份内容**。带上 query 会让"问 10 次同一个主题"产生 10 倍的卡，账本全是重复。这直接违背 `cardId` 的既有契约（注释明写"刻意不含 retrievedAt/fetchedBy同一段原文被两个 agent 各抓一次仍是同一张卡"）。
- **`sourceTier` 从 `SourceHit` 推断，不要求显式传**：调用方更省事。否决理由：**层级是权威性的一部分**，而 `SourceHit` 里没有这个信息（它来自召回的哪一层，只有调用方知道）。推断只能是猜，猜错的层级会以错误的可信度进入证据链。
- **把 `sourceId` 映射成 `PlatformId` 联合类型的成员**：类型上更"正确"。否决理由：`sourceId` 是接口名（`crossref`/`mdn`/`github`），不是平台名；**映射会丢掉"这条来自哪个具体接口"**，而这个信息是审计要用的。类型断言加注释说明，比一个会丢失信息的映射诚实。
- **在 `recall()` 内部自动落账**（让召回自己沉淀）：调用方什么都不用做。否决理由：`recall` 是**纯查询**，把它变成有副作用会让"我只是想看看有什么"也写进账本。而账本是**只追加**的写错了擦不掉。副作用必须由调用方显式发起。

## Consequences

- **第 (4) 项需求的回路第一次闭合**：`recall()` → `sinkHits()` → `EvidenceLedger` → `buildIndex()` → `query()`。端到端测试证明"搜到的东西能被下次会话检索回来"。
- **幂等**：同一份内容重复沉淀是 no-op（内容寻址）。这是**"可全量重建"的前提**只要能重新取到同样的内容，账本就会收敛到同一个状态。
- **数据质量问题可见**：`skippedNoQuote` 计数与 `sinkDigest()` 让"有几条因为没有可核对原文被跳过"出现在输出里，而不是静默丢弃。
- **`provenance` 如实记录来源类型**：`argo:*` 记为 `metasearch`（经了第三方引擎），其余记为 `api`（直连）。两者可信度不同。
- **仍未做的**：桥建好了但**没有调用方**（与 `resolve.ts` 同样的处境）。把 `sinkHits` 接进一个端到端入口需要先决定"谁在什么时候沉淀"（每次召回都沉？还是 agent 显式命令？）那是策略决策，不是实现细节，本轮刻意不做。

## Verification

- `bash components/HX-Sagasu/scripts/test.sh` → **179 tests / 179 pass / 0 fail**（新增 12 项）
- 端到端：`sinkHits` 沉淀 → `buildIndex` → `query('所有权')` → 命中，且 `query()` 返回的 `cardId` 能在账本里查到（索引只存指针，正文留在账本）
- 契约测试：url 永不进 quote、两者都空时拒绝造卡并计数、同内容重复沉淀是 no-op、同 URL 内容变了是另一张卡、`sourceTier` 必须显式给出、`argo:` 记为 metasearch
- **一处自省**：我第一次写这项测试时断言 `found[0].card.quote`，而 `query()` 返回的是 `{cardId, score, matched}`**索引只存指针**。测试当场失败。这不是测试写错，是**我忘了自己定的契约**（"Ledger 是真相、Index 是派生品"）。修法是把断言改成"从 cardId 回账本取卡"，而这恰好让测试多验证了一条不变量：**索引里的 cardId 必须能在账本里查到，否则索引成了孤儿**。
