# Agent Note: 对话语义上界面  以及一个让"楼主"全部标不出来的字段误读

Status: implemented

- 影响: `components/HX-Sagasu/scripts/serve.ts`（`/api/thread`）、`scripts/page.ts`（对话面板）

## Problem

目标第 (3) 项的四个子能力（错别字容错 / 帖子-回复结构 / 引用链 / 多轮上下文）
**此前只在 CLI 上可用**  界面既没有 thread 端点，也不呈现任何对话结构。

而**界面是本项目唯一"让人看见"的地方**：目标第 (2) 项的平台可用性就是靠面板
才从代码注释变成屏幕上的一行字（见 `2026-09-18-platform-visibility.md`）。

**同一个道理**: 引用链指回了哪一楼、楼主是谁、这句话在对哪一楼说 
如果只在 CLI 输出里，那它们就只存在于"读过那次输出的人"的记忆里。

## Decision

**加 `/api/thread` + 界面面板。**

面板要能看出三件事（每一条都对应一个真实需求）：

1. **哪些楼层是楼主的**  引用链的落点（`.turn.op` 高亮）
2. **提问解析到了谁、依据是什么**  **依据必须显示**，否则没法判断解析对不对
3. **没解析出来时为什么 + 怎么消歧**  "楼上"需要阅读游标时，面板要给出
   "在上面填楼层号"这个可操作的动作（**报出问题必须同时报出解法**）

### 界面不写账本（刻意）

CLI 的 `--sink` 是**显式**副作用；界面是观察工具，
不该因为有人点了按钮就往**只追加**的账本里写东西。
**抓取与对话证据的沉淀必须由调用方显式发起。**

## 一个字段误读（本轮的实际 bug）

第一版服务端我写的是：

```js
isOp: t.author !== undefined && 'isOp' in t ? t.author.isOp === true : false
```

**实测 `isOp` 全是 `false`**  界面上"楼主"一个都没标出来。

真因：**`isOp` 在 `participants` 上，不在 `turn.author` 上**
（`thread.ts:118` 用 `input.opAuthorId` 给 participant 打标，
`resolve.ts:52` 读的也是 `thread.participants.filter(p => p.isOp)`）。

改成读 `participants` 后实测：

```
楼主楼层: [(7, '老咸鱼A'), (10, '老咸鱼A')]
```

**而这个 bug 有一个更坏的版本**：我最初甚至没意识到要去核对 
是**界面探针报出 `opTurns: 0`** 才暴露的。CLI 侧一直是好的（它不用这个字段），
**所以"功能正常"与"界面正确"是两件事。**

## Alternatives considered

- **只做 CLI，不做界面**：省掉一个端点和一块 UI。**否决理由**：CLI 输出是一次性的、滚过就没了；面板是**常驻的**。而且第 (3) 项的验收判据里有一条是"必须回到**具体楼层**并给出原文引用" 那在界面上比在 CLI 里更容易被验证。
- **界面复用 CLI 的输出文本**（把 `cmdThread` 的打印结果贴进 HTML）：实现最省。**否决理由**：CLI 的输出是**为终端排版**的（固定宽度、padEnd 对齐、`#r376080139` 这样的截断 id）。贴进 HTML 会得到一个既不像终端也不像网页的东西，而且**失去可点击/可高亮的可能**。
- **界面也让用户填 `turnId` 而不是楼层号**：与内部表示一致。**否决理由**：**人不会去数 hash**（与 CLI 的 `--at` 同一个理由，见 `2026-09-18-cursor-multiturn-wired.md`）。界面接受序号，服务端转 id。
- **把 `isOp` 判断改成"作者出现在首楼就算楼主"**：能绕开 `participants` 的结构。**否决理由**：**那正是 `resolve` 的 0.6 置信度回退路径**（无 isOp 标记时）。而这里 `participants` **确实带 isOp 标记**（B站适配器传了 `opAuthorId`） 有精确判据却用近似判据，会让界面与 CLI 显示**不同的楼主**。
- **在界面里也提供"沉淀进账本"按钮**：功能更完整。**否决理由**：账本是**只追加**的，写错了擦不掉。界面是多人可能点到的地方，不该有单向副作用按钮。**沉淀必须走 CLI 的 `--sink`（显式、可审计）。**

## Consequences

- **`/api/thread?ref=<平台>:<id>[&ask=…][&at=…]`** 返回楼层、楼主标记、指代目标与依据、歧义与消歧提示。
- **界面新增"问帖"面板**：填引用 + 提问 + 可选游标，点"问帖"。
- **界面仍不写账本**（见上）。
- **未做**：`parentId`/`quotedTurnId` 的**回复树**在界面上仍未呈现（只按楼层顺序平铺）
  这是第 (3) 项"帖子-回复结构"的最后一个未呈现部分。
