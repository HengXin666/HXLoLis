# Agent Note: 证据链兜底  补上「失败了最终给什么」

Status: implemented

- 影响: `components/HX-Sagasu/src/fallback.ts`（新建）、`scripts/sagasu.ts`（`search` 输出接入）

## Problem

本组件的失败契约是：**取数函数失败必须抛**（`[]` 只表示「真的跑了但没有内容」），且失败要**响亮**（`failures` 逐条上报）。**这些都成立、也都对。**

**但它们只回答了「失败了怎么办」的一半**  失败了，**最终给用户什么？**

此前是：`hits` 里有多少算多少，失败进了 `failures`，然后**没有下文**。于是两种处境输出**长得一样**:

| 处境 | 内部状态 | 用户看到的 |
|---|---|---|
| **确实是空**（跑通了，就是没有） | `hits=[]`, `failures=[]` | 空 |
| **全线崩溃**（网络断/会话坏/来源全挂） | `hits=[]`, `failures=[18 条]` | **也是空** |

**两者的正确应对完全相反**: 前者该如实说「没有」，后者该说「没搜到，但这是故障不是结论」。

学自 aether-search 的「证据链接兜底」 它分三级降级（Grok → agent → 证据链接），**把「降级到什么」想清楚了**，而不是只把失败报出来。

## Decision

**三档产出，判据只有「有没有真实证据」与「有没有失败」两条。**

```
  'answer'    hits 够用且无失败  正常返回（不打扰）
  'answer'    hits 为空且无失败  **明说「确实没有，不是故障」**
  'partial'   有证据但有失败  **证据 + 明确标注它是局部的**
  'degraded'  无证据且有失败  **明说这是降级，不是空结果**
```

**数量阈值不在这里管**  那属于充分性判断（`SufficiencyVerdict` 已经在管）。本模块只管**装配**。

### 为什么 `answer` 有两个分支

「hits 为空且无失败」**也要说话**  否则用户分不清它和故障。这条是「确实没有 ≠ 故障」那个区分的另一半。

### `isDegraded` 的语义

**只有 `degraded` 才算「结果不可信」**。`partial` **不算**  它有真实证据，只是不完整。把两者混为一谈会让用户**丢掉本来可用的证据**。

## Alternatives considered

- **什么都不做**（现状）：用户自己在 `failures` 里看。**否决理由**：`failures` 是**结构化诊断**，而普通输出里它只显示「✖ 失败 xxx」逐条  **用户要自己推断「所以这次结果能不能信」**。把推断留给用户，等于把这件事做了一半。
- **在数量阈值上加兜底**（如 hits < 3 就报 partial）：更「智能」。**否决理由**：**阈值属于充分性判断**，那里已经有 7 个信号（volume/topic-fit/language-fit/source-diversity/…）且有 `stoppedBecause` 解释。在这里再放一个阈值就是**第二套判据**  而本项目的教训是**两套判据会漂移**。本模块只看两个**布尔**事实。
- **`partial` 也算不可信**：更保守。**否决理由**：**那会让用户丢掉本来可用的证据**。`partial` 的正确表达是「这是部分证据」，不是「别信它」。
- **抛错而不是产出兜底结论**：与「失败要响亮」一致。**否决理由**：**那会把「某个来源失败」升级成「整次检索失败」**  而第 0 层可能是好的、结果可用（实测 24 条命中）。响亮指的是**上报**，不是**中断**。
- **让 `recall` 自己产出这个结论**：少一个模块。**否决理由**：`recall` 已经在管分层、路由、充分性、事件流；**「最终怎么呈现」是另一个关注点**。而且纯函数放在外面**可被穷举单测**。

## Consequences

- **两种空结果不再混同**  这是本模块存在的全部理由。
- **`fallbackOf` 是纯函数**（只读 `RecallResult`，不碰网络） 于是可被穷举单测。
- **`renderFallback` 供 CLI 直接打印**；`isDegraded` 供调用方决定要不要继续用这批证据。
- **实测发现**: 真实来源**很健壮**  我用一个必然无结果的查询（`zzqqxx99 nonexistent term 404`）**仍拿到 12 条**，造不出「全线失败」。所以 `degraded` 分支靠**注入必失败取数器**验证。

## Verification

- `bash components/HX-Sagasu/scripts/test.sh` → **305 tests / 305 pass / 0 fail**（新增 7 条）
- **端到端**（`search "Rust 所有权"`）: 命中 24 条后输出 `结果不完整：2 个来源失败，以下是**已取到的部分证据**`
- **`degraded` 分支**（注入 11 个必失败取数器）: `tier0 失败数: 11 | 命中: 0` → `等级: degraded | isDegraded: true`
  ```
  渲染: **降级**：18 个来源失败，且没有取到任何证据
        这不是"搜不到"是**这次检索本身出了问题**。请检查网络/argo 会话，或稍后重试。
        **不要把空结果当成结论。**
  ```
