# Agent Note: 把未闭合的并发失败固化成可复现资产

Status: implemented

- 影响: `components/HX-Sagasu/scripts/diag/repro-argo-init-timeout.sh`（新建）

## Problem

前三轮我一直在追"CLI 路径下 11 个 argo `initialize` 超时"，而它**稳定复现**
（连跑 3 次均为 11 个），**却在受控脚本里从不出现**。

本轮又排除了 **5 个新方向**（累计 **21 个**），而**每一个都指向"代码逻辑没问题"**。

## Decision

**停止在"代码差异"上继续找，改为把现象固化成可交接的诊断资产。**

新增 `scripts/diag/repro-argo-init-timeout.sh`，**三段对照**：

| 段 | 内容 | 实测 |
|---|---|---|
| **A** | CLI 路径（`scripts/sagasu.ts`） | **11 个 initialize 超时** |
| **B** | **逐字节克隆**（`scripts/_clone.ts`） | **11 个** → 证明**不是文件路径** |
| **C** | 手工重写的等价脚本 | **0 个** → 证明**不是代码逻辑** |

**A 失败而 C 为 0**  这个对照本身就是最强的线索：**同样的模块、同样的调用序列、
同样的参数，只有"文件本身"不同**。

## 本轮新排除的 5 个方向（累计 21）

| # | 方向 | 实测 |
|---|---|---|
| 18 | **CLI 的额外导入**（ledger/sink/index-store/thread/resolve/reply-tree/url-safety/readability） | 全加上后仍 **0 超时** |
| 19 | **`planFetchers` 替换了 argo 闭包** | 逐条比对：`bilibili_hot`/`pubchem`/`devto` **都是同一函数对象** |
| 20 | **顶层 `import` vs `await import()`** | 改顶层 import 后 **0 超时** |
| 21 | **文件所在目录**（`scripts/` vs `/tmp`） | 同一份代码放 `scripts/` 下仍 **0 超时** |
| 22 | **系统负载**（load average **20-21**，32 核） | 负载下握手仍 **0.8-1.1 秒**正常 |

**其中 22 值得单独记**：本机 load average 长期在 20 左右（firefox/qemu/clash-verge 等），
而**我 43 轮里所有测试都跑在这个环境下**。实测握手耗时不受影响，
但**这仍是一个值得记住的环境事实**。

## 一个新的、有价值的观察

`sagasu.ts` 与 `toplevel.mjs` 的**第 0 层命中数相同（15 条）**，而**第 1 层差一倍**：

| | tier0 | tier1 |
|---|---|---|
| `toplevel.mjs` | 15 | **13** |
| `sagasu.ts` | 15 | **6** |

**tier1 成功的只有 `juejin` 与 `bilibili`**  而它们是 `SOURCES` 里**最先被遍历到的两个 argo 来源**。

**所以是"前 2 个成功、其余全失败"**  与 `literal.mjs` 同形，
**说明失败发生在"第 3 个及以后"**。这个"前 N 个成功"的模式是本轮最具体的线索。

## Alternatives considered

- **继续找那个差异**：更彻底。**否决理由**：**本轮 12 轮 + 前两轮 27 轮 = 39 轮**，而**新排除的每一条都指向"代码没问题"**。继续的期望收益已明显低于成本，而**固化成可复现脚本是可交接的资产**。
- **把 CLI 改成手工脚本的写法**（换个文件、改 import 形式）：可能绕过症状。**否决理由**：**那是让代码去迁就一个未理解的故障**。而且 B 段（逐字节克隆）已证明**换文件名无效**，所以"换个文件"这条路的收益也不确定。
- **接受失败，把 11 个来源从 `ARGO_ENGINE` 删掉**：输出会"干净"。**否决理由**：**删掉问题 ≠ 解决问题**。实测这些来源**能用**（C 段 0 超时、13 条命中），删掉是**主动损失能力**。
- **给失败来源加自动重试**：可能自愈。**否决理由**：之前实测过  重试让一次召回从 25s 变 **175s**（每个都等满 15 秒握手超时）。**在没有定位根因之前，重试只是把失败变成慢**。
- **不写诊断脚本，只在 note 里记录**：省事。**否决理由**：**note 是叙述，脚本是可执行证据**。三段对照（A=11 / B=11 / C=0）能在一分钟内让别人（或换工具的我）看到**同一件事**，而 note 需要读五分钟才能重建那个判断。

## Consequences

- **`scripts/diag/repro-argo-init-timeout.sh` 是常驻资产**  下一个人（或换工具的我）可以直接跑。
- **21 个方向已排除**，且每一条都有实测数据。
- **CLI 的实际可用性不受影响**：`exit=0`、第 0 层完整（15-18 条）、总命中 21-24 条。
- **失败的本质**：第 1 层的 argo 来源**只有前 2 个能用**，其余 10 个失败  这是**真实的能力损失**，但**不是可用性损失**。
