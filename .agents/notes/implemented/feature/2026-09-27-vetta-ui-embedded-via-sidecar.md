# Agent Note: 设计系统演示走博客原生侧车, 而不是把组件塞进站点

Status: implemented

- 影响: `components/HX-VettaUI/scripts/build-standalone.mjs`（新建）、`ai-docs/002-程序语言/003-Web前端/002-OpenVetta界面设计系统拆解/ui-showcase.html`（新建）
- 相关: [2026-09-27-vetta-ui-design-system-package](2026-09-27-vetta-ui-design-system-package.md)

## Problem

`HX-VettaUI` 是一个 Tailwind **4** 的包（靠 `@theme inline` 把 CSS 变量桥接成工具类）。
HXLoLi 站点是 Tailwind **3.4** + PostCSS。两套主题机制不兼容：把包的类名直接搬进站点，
`bg-primary/10` 这类工具类不会生成，页面会静默地少掉全部样式。

而演示页必须进站点  一个只能本地 `vite preview` 的演示，读者看不到，也就谈不上验收。

## Decision

**把整页打成自包含单文件 HTML, 用博客已有的 `#ppt` 侧车机制内嵌。**

### 为什么不是把组件 import 进站点

改站点到 Tailwind 4 会波及 32 篇笔记与整个主题层，收益却只有"一个演示页"；
而把包降级到 Tailwind 3 会毁掉 `@theme inline` 这一整套换肤机制  那是本包的核心。

侧车 iframe 本身就是**独立文档**，天生带样式隔离。既然它不共享宿主的 CSS 上下文，
"两套 Tailwind 不兼容"这个前提就不成立了。

### 为什么不用 `.tsx` 内联演示页

站点有 `.tsx` 内联演示页（`##PPT##` + `npm run decks`），它融入站点主题、能实时换肤，
是站内演示的默认选择。**这里不适用**：`.tsx` 也是被 webpack 用站点的 Tailwind 3 管线编译的，
同样会丢样式。它不是一条绕开构建链的路。

### 三条硬约束（少一条就是空白 iframe）

1. **指令是 `#ppt`，一个井号。** 解析器认 `/(^|\s)#ppt(?=\s|##|$)/`，写成 `##ppt` 匹配不上；
   而 `A.tsx` 要求 `target === 'html' && hasPptMark` 才走 iframe 分支  匹配不上时整条链接
   **静默退化成普通文本链接**，不报任何错。这次就先踩了这个坑。
2. **侧车必须与 `index.md` 同目录。** `ppt-html-assets` 插件只给"同目录有 md"的 html 建拷贝表。
3. **产物必须自包含。** 内联 CSS/JS、无外部相对资源、不依赖宿主 DOM。

### 嵌入态要显式降级

iframe 里可用高度常常只有 460~560px（16:9 卡片），而桌面窗口是 800~1000px。
根元素检测到 iframe 就打 `data-embedded`，据此:

- 隐藏 `.drag-region`  `-webkit-app-region` 在 iframe 里拖的是宿主页面，占的 44px 是纯浪费；
- 隐藏主题切换按钮  站点自己有亮暗开关，两个入口会打架，而且它盖住右下角内容；
- 矮视口（`max-height: 720px` / `560px`）下收紧留白与侧边栏密度。

## Alternatives considered

**站点升到 Tailwind 4。** 最强的理由是它一次性解决两套主题机制并存的问题，往后所有包都能共用。
否决它的原因:波及 32 篇笔记的既有样式与整个主题层，而本次的收益只是一个演示页 
收益与影响范围严重不成比例，属于拿架构换取局部便利。

**把包降到 Tailwind 3。** 最强的理由是站点零改动，且 Tailwind 3 的生态兼容性更宽。
否决它的原因:`@theme inline` 是这套设计"换 token 即换肤"的唯一载体，降级意味着
`tokens.css` 里那套机制整个作废，包的核心价值随之消失。

**写成 `.tsx` 内联演示页。** 最强的理由是它融入站点主题、与正文观感一致、还能实时换肤，
是站内演示的既定首选。否决它的原因:它同样由站点的 Tailwind 3 管线编译，样式照样会丢；
而且它表达的是"幻灯片"这一形态，装不下一个带侧边栏与滚动区的完整应用界面。

**只放静态截图。** 最强的理由是零构建成本、体积最小、不会失效。
否决它的原因:截图无法验证"这套东西装起来到底能不能用"，而这恰恰是本次要交付的东西 
上一轮就交付过一堆全绿但难看的东西，静态截图正是那种交付的形态。

## Consequences

- 演示页多一步构建：改完包必须跑 `npm run build:standalone` 并把产物拷进笔记目录。
  产物 320 KB，已进版本管理（侧车要求与 md 同目录，无法 gitignore）。
- 嵌入态与独立打开是两种形态，改动 UI 时两边都要看一眼。
- 侧车是 iframe，**换不了主题**  它固定跟随自己的 `data-mode`，不跟随站点亮暗切换。
  这是 `.tsx` 形态才有的能力，属于本次主动放弃的一项。
- 这次的关键教训已写进 README 与笔记：`#ppt` 写错时**没有任何报错**，只表现为链接不能点。
  凡是"解析失败即静默退化"的入口，都必须实测，不能靠读文档推断。
